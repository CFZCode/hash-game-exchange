## Help Center / Provably Fair

`/help/:helpId`, and `/help` redirects to `/help/provably-fair` — a real redirect the chunk performs itself (`pathname === "/help" && navigate("/help/provably-fair", {replace:true})`), not a default route, which is why Provably Fair is the lit row in the capture.

**This page is not in the main bundle at all, and that is the finding worth carrying forward.** It is **Module Federation**: `Enter-MsmOuq5R.js` resolves the shell through `h = zt(yo)` where `yo = () => import("/modules/static/remoteEntry.js")`, and the Provably Fair body through `X = zt(Io)` where `Io = () => import("/modules/games/remoteEntry.js")`. There are three remotes — `account`, `static`, `games`. The mirror saved `account` and `games` but **not** `static`, and neither saved remote carries its lazy chunks.

**The `hash.game` trick works one directory up.** `hash.game/modules/<name>/remoteEntry.js` re-exports a `manifest-*.js` holding both the exposes map and that remote's own `__vite__mapDeps` table, and every chunk hangs off `hash.game/modules/<name>/assets/`. So when a component is not in `/assets/`, check whether it is a federated remote before assuming it is unrecoverable — that is how `index-Buajimh5.js` (HelpCenter), `ProvablyFair-CJEm-Nog.js`, `GameFairnessFile-DEzcpem0.js` and all thirty fairness documents were recovered.

**Documents are per-locale lazy chunks, not inline strings.** Both `createHtmlFile-Bp8HPAMX.js` (help topics) and `GameFairnessFile-DEzcpem0.js` (game fairness) are glob maps of `locales/<lang>/…/<name>.html` to their own chunk. There are 21 en-US help documents and 30 en-US fairness documents. **The 30 fairness documents are extracted** into `src/pages/Help/fairness/*.html` and loaded with `import.meta.glob(..., { query: '?raw' })` — they are the Provably Fair dropdown's own content. The 21 help documents are **not** bundled: the other sixteen rail rows route correctly and render an empty pane. Their chunk filenames are recorded in `createHtmlFile-Bp8HPAMX.js` if they are ever wanted.

**The rail is seventeen rows in the capture's order**, which is *not* the routesMap's key order — the chunk merges three objects to build the map and takes the order from a separate array. The map holds more ids than the rail shows (`about_us`, `bonus`, `providers`, `contact_us`, plus a whole licensing-microsite family). `element` is the document id, not the route id, and they differ: `coinlimit` → `coin_limit`, `reglog` → `registration_login`, and **both** `gameble-aware` and `protect-minors` render the same `gamble_minors` file. `gameble-aware` keeps the original's misspelling — it is the real path and the footer already links to it.

**All 17 rail icons are the original's**, extracted from the `static` remote — 14 inline in `index-Buajimh5.js`, three (Terms Of Service, FAQs, Support) in their own IconBook/IconHelp/IconHelper chunks. They carry no `fill`, exactly like the BetBy sprites, so the rail colours them with `fill-current`. Regenerate rather than hand-edit. Two traps hit while generating them, both already documented for BetBy and both real here: Solid's templates leave `<path>` **unclosed**, which JSX rejects; and the 18+ mark ships a `<clipPath>` whose `<rect>` is the full 32×32 viewBox — it clips nothing, and inlining a duplicate id on every page breaks later references, so it is stripped along with the `clip-path` attribute pointing at it.

**BELOW 1024 THE RAIL IS NOT NARROWED, IT IS REPLACED — and the page is a dialog.** `{ component: h("Layout"), path: "/help", info: { dialog: m.mobile } }`, with the flag on the LAYOUT, so both `/help` and `/help/:helpId` ride one sheet and switching topics never remounts the shell. A bare `dialog` with no `behavior`, so it takes the ordinary opaque title bar — the third of the three arms, beside `/vip-detail`'s `transparent-title` and `/bonus`'s `no-title`. `h("Layout")` draws nothing at all (`Layout-BSXc1KNv.js` is `function e(t){return t.children}`); the "Help Center" string comes from the page's own `PageLayout`, which is why the desktop arm draws an `<h1>` instead.

The mobile half is `o2` and it is three elements: a `sticky top-0 z-20 bg-layer2 py-4` section holding the site's own `Select` over the route ids, and a `page-info mb-4 rounded-xl bg-layer4` card for the document. The Select needs no mobile arm of its own — `components/shared/Select` already opens as a bottom sheet below lg, which is where the capture's "Select" title and drag handle come from — and it passes NO `size`, so it takes `.button`'s bare 3rem rather than `button-m`'s 2.5. That is measured, not assumed: the trigger is 44px in a capture whose title bar is 52px, i.e. 3rem against `--safe-header`'s 3.5rem at a root of 14.86px. `page-info` is dead in all three stylesheet sets and is kept.

**The mobile Select lists EIGHTEEN rows where the rail lists seventeen, and the extra one is blank.** `c2()`'s route array carries `limit-game`, which has no entry in the routesMap; the desktop rail is built with `if (C.routesMap[u])` and silently drops it, while the Select is handed the raw array (`options: C.routes`) and renders a labelless row with a radio button. The phone capture shows it as the fifth row. `ROUTE_IDS` in `topics.js` is that array, reproduced rather than tidied.

The dropdown is the site's own `Select` over `/game/home/recommend/selection/` with `selectionName: "originals"` — the same endpoint the home page uses, so no path is invented. Two filters are the chunk's own and are reproduced: drop any row whose slug contains `trenball` and any whose name contains a colon. That leaves 37 rows with **Crash** first, matching the capture, since the chunk seeds the Select with the feed's first row rather than shipping a default. 22 of them have their own fairness document; the rest fall through to `general.html`, which is the chunk's `F[gameUnique] || "general"`. The Validate button opens `game-verify.github.io` and only appears for games with a `validateLink` in the games remote's config — 40 of them, and the mapping is not a rename (`cave` → `slots.html`, `keno` → `keno_single` while `keno-multiplayer` takes plain `keno`).

## Responsible Gambling

`/responsible/:responsibleId`, and `/responsible` bare — the Help Center's sibling in every sense. `Enter-MsmOuq5R.js` routes both through `h("ResponsibleLayout")`, and `h` is the same `/modules/static/` remote, so the layout chunk (`index-CdxGH7-n.js`) came off `hash.game/modules/static/assets/` by the identical route one directory over. It shares `Help.css` and the Help Center's sticky arrangement deliberately: heading pinned at 60 under the rail, rail at 120 with the higher z-index so it covers the heading once the container's bottom carries it up.

**All five rows are built, and only ONE of them is a document.** FAQ's is the `responsible_gambling` HTML file, which was already extracted for the Help Center and is imported from there rather than duplicated — which is why `element` is `null` on the other four rather than missing: they are **components in the remote, not documents**. Self-Assessment is written inline in `index.jsx`, and Gambling Limits, Self-exclusion and the Budget Calculator are their own files, all from rendered DOM.

Three things that fall out of that split:

- **The document row is FLAT, not an accordion.** It has the same `<section>`/`<h2>` shape as a help topic, but the captures show every heading and its prose expanded down one column with no chevrons anywhere, so `toSections` is not reused from the Help Center. The chunk also lifts each `<h2>` OUT of its own section, which is why the rendered `<section>` elements open on a blank line.
- **Three panes bring their own card and one does not.** Gambling Limits, the Budget Calculator and Self-exclusion each supply their own `rounded-xl bg-layer4` wrapper (Gambling Limits two of them, side by side) and render straight into the page container; only the document rows sit inside the container's single box. Self-exclusion additionally takes the "Need Help?" column beside it, in one `xl:flex-row` wrapper rather than as a third item on the page's own row.
- **None of the shared document styling reaches a component pane** — no `help-center-box`, no `help-doc` — so their spacing is stated per element (`mt-0` then `mt-4` then `mt-3`) and a title is a `<p class="font-extrabold text-primary">` rather than an `<h2>`.

The badge strip under the first heading is the remote's own `rg-BrECRvg0.png` at 1066×160, saved as `rg.png`; `sm:w-1/2` is the original's, which is why it spans only the left half. Its light-theme twin (`rg_w-Ba_NNOY-.png`) is one of the theme holes listed under Light theme.

**BELOW 1024 IT IS A DIALOG AND THE RAIL IS REPLACED BY A SELECT — the Help Center's mobile arm one for one**, which is what you would expect of a page whose whole shell is that page's. `bn` is `<Show when={re.mobile} fallback={<Desktop/>}><Mobile/></Show>`, and the mobile half is a `sticky top-0 z-20 bg-layer2 py-4` section over a `page-info mb-4 rounded-xl bg-layer4` card, with the "Need Help?" block as a third sibling under it rather than a column beside it. `useIsDialog()` is what the page branches on, which is the router's own context rather than a prop.

Three things differ from the desktop arm and two of them are the chunk's:

- **The card is unconditional.** `jt` wraps whatever `element()` returns, so a pane that carries its own card (Gambling Limits' two, Self-exclusion's one) sits inside a second one. The desktop `o()` is per row — and note `noContainer` is set on exactly ONE row and set to **false**, so on the original every row gets a container there too. This build's desktop arm gives it only to document rows; recorded rather than corrected, since changing what a desktop renders is not part of building a phone layout.
- **"Need Help?" belongs to TWO rows, not one** — `["self-exclusion","gambling-limits"]`, and the same list on both arms of the chunk. The mobile arm here reproduces it; the desktop one still gives it to self-exclusion alone, same reasoning.
- `pageGutter={false}` at the mount, alone among the `PageDialog` routes: this page carries no `px-4` of its own on either arm, so the inset has to stay on `.dialog-content` where the chunk leaves it.

## VIP Club

`/vip-detail` — the original's own path (`component: c(() => L.VipDetail())`), and what the sidebar's VIP Club row means; that row already carried the `vip_club` sprite and had nowhere to go. `/vip` is its alias, carrying `guards: [() => "/vip-detail"]` — a guard that returns a path is a redirect in that router — so it is a `<Navigate>` here. `/vip-offer` is a sibling and is not built. `/vip-level` is built — see Tiers & Benefits below.

**BELOW 640 IT IS A `transparent-title` DIALOG, and the flag that decides it is the page's own 640 one rather than the project's usual 1024.** The route is `dialog: m.mobile ? {behavior: "transparent-title"} : !1`, and the title comes from the PAGE: `Mt`, the chunk's root, is `<Show when={S.mobile}>` wrapping the same children in a `PageLayout` whose title is a `size-5 fill-[#FFE924]` `IconVipclub` beside "VIP Club" — and `w3` draws nothing, so that string only ever surfaces as the manager's title bar. Both are one `mobile` flag on the original, so they have to flip together here, and this page's is 640 for the hero-gutter reason documented below. It is also forced from the other side: `transparent-title` zeroes `.dialog-content`'s horizontal padding, which makes the page root's own `px-4 sm:px-0` the sheet's gutter — and that padding is gone from 640 up. `pages/VIP/Dialog.jsx` is the mount; the page file is untouched by it.

That is also what turned up a bug in the shared shell. `no-title` (which `/bonus` uses) is written as a transparent-title dialog TOO — `(v || y) && "dialog-transparent-title"` — so the pair of rules that make a floating bar work both applied to it: the negative margin cancelling `.dialog-item`'s `padding-top: var(--safe-header)` is correct for both, but the compensating `padding-top` on the scroll container is guarded `:not(.dialog-no-title)` on the original and was not here. Without the guard a no-title sheet started 56px down AND its scroller ran 56px past the bottom, putting the last 56px of the page out of reach. **`info.backgroundColor: "195 113 28"` is deliberately not reproduced**: the manager writes it as `--bg` on `.dialog-content`, and the only consumer of `--bg` in any of the six stylesheets is `.dialog-title`, which is that element's SIBLING and sets its own — so it reaches nothing.

**This is the first page where nothing is inferred, and the reason is the method, not the page.** `index-DLlkBGhd.js` is missing from the mirror, so by the rules the rest of this file was written under it would have been a screenshot rebuild. Instead the chunk came off `hash.game` (see the mirror note above), along with its asset module `index-BGw8Rzb9.js`, `vip-service-CYiVi9f2.js`, and all eighteen PNGs. So the copy in `pages/VIP/vip.js` is verbatim `t("…")` out of the chunk, the class lists are the rendered DOM's, and the artwork is the deploy's own files under their hashes stripped. **Prefer this route over transcription on every remaining page.**

Consequences worth knowing before touching it:

- **`bg-from-special` on every perk card is a dead class.** It is not in the page's stylesheet (`detail-CKVlkrmQ.css` is one unrelated `.sport-icon-svg` rule), not in the saved main bundle, and not in the current deploy's either. The card is therefore `from-layer4 !to-layer4` — a gradient between one colour — and samples flat `#323738` in the capture. The `!` on the second stop is the tell: it was written to beat a rule that no longer ships. `inactive` on the hero link is dead the same way. Both are kept.
- **The FAQ rail is two tabs and a link, not three tabs.** "Terms Of Service" is `window.open("/help/terms-service", "_blank")` and never takes the `bg-layer5` pill, which is why `kind` is stored per row rather than inferred from position. The accordion is the shared primitive's **Single** mode (`ck` defaults to `bh.Single` and this call site passes no `multiple`), so one open row closes the last, and the chevron is `rotate-180` closed / `rotate-[270deg]` open.
- **Five things branch on sign-in**, all off `session.login`: the hero's Join Now button, the entire VIP Transfer block under the film, the hero container's `mt-3`, the hero backdrop's whole class list, and the perks heading's `sm:mt-6`. The signed-in page has no level card — the chunk's legacy branch that draws one sits behind a `Show` with `when: !0` and can never render.
- **The banner is a JS branch, not a `lg:` pair.** Desktop is a crown plus two flanking coins; mobile is one wider image and no coins, over a different background file. Rendering both and hiding one would put four images on every phone. **`S.mobile` is read as the 640 line here, not the 1024 line the rest of the project uses for that flag** — the one deliberate exception, and the markup forces it: the hero's mobile arm is `-ml-4 w-[calc(100%+32px)]`, which exists solely to cancel the page root's `px-4 sm:px-0`, and that padding stops at 640. Gated at 1024 instead, every width in 640–1023 gets the negative margin with no padding left to cancel and the banner sits 16px past the gutter and 32px overwide. The image swap moves with it rather than keeping its own breakpoint. What is lost is that `S.mobile` is a DEVICE test — a phone in landscape at 844×390 is mobile to the original, which is what the `sm:` variants inside both banner templates serve — and no width query can express that.
- **`--spacing-sh` is new in `@theme`**, and it is the original's own name: `.pt-sh` is `padding-top: var(--safe-header)` and `.app-root` sets `--safe-header: calc(var(--header) + var(--safe-top))` with `--header: 3.5rem`. Declared flat rather than as that calc on purpose — the only consumer is an `sm:` variant, where `--safe-top` is 0, and declaring the variable globally would also reach `.dialog-item` in `Auth.css`, which currently renders on its `0px` fallback. It **stacks on top of** `.main-layout-content`'s header offset, which is correct: `#page-content` on the original carries the identical padding AND the page root adds `pt-sh` inside it.
- The film stays remote (`img2.distributedresourcestorage.com`), the one asset the original itself serves off a CDN; its poster is local like the rest. The light-theme backdrops (`banner_bg_w`, `banner_bg_m_w`) were deliberately not fetched — this build is dark-only, so the chunk's `r[+S.mobile<<1 | +!W.darken]` index can only reach the even entries.

`ENDPOINTS.vip` holds four real paths read out of the recovered modules, but the page calls none of them: its copy is i18n compiled into the chunk. `support` is used only as the seam `services/vip.js` hands the fixture through; `rankInfo` and the two `offer` calls drive the signed-in level and deposit-offer widgets that are not built.



## Tiers & Benefits

`/vip-level` — `L.VipBenefits` → `tier-benefits-Djqjq-tJ.js` + `tier-icon-uERoa3jE.js`, both off `hash.game/assets/`. **A dialog at every width**: the route has no `info` inside `$g`, which is `Y([...], {dialog: !0})`, so it takes the manager's default 30rem x 40rem card (full-screen sheet below lg). No guard; signed out it renders Beginner as current. Root is `PageLayout title="Tiers & Benefits"` with `bonus-scope bg-layer1 …` on `.dialog-item` (RouteDialog's `itemClassName`). The page is a vertical timeline of tier families (Beginner … Eternal): the current tier is bordered, pulsing (`vip-ripple-ring`, transcribed into `pages/VipLevel/VipLevel.css`) and opened by default; each family expands to its sub-levels with a Level / threshold table; the NEXT tier shows its benefit line as a teaser. Entry point: the /bonus Level card's arrow. The VIP Club page's "Learn more VIP level up system" button is in its never-rendered `Bt` branch, so it is not added.

Data: `GET /user/vip/levels` (`services/vip.js` `getVipLadder`, the fixture is the captured ladder in the same shape) and `GET /user/vip` (`getVipStanding`) for the current level and wager. **Departure, on request**: thresholds and the current tier's subtitle print as wager in the header currency (`cur.show`) under a "Wager" column instead of "XP", since the platform's ladder is USD wager. Eternal's "Exclusive title & top-level achievements." is dropped — nothing on this platform backs it.

# Signed-in header, the currency dropdown, and the mobile account page

Part of the bc.game rebuild notes. Index and cross-cutting rules: [../CLAUDE.md](../CLAUDE.md).

## Signed-in header

What the header becomes once `session.login` is true — `src/layouts/MainLayout/Header/AfterLogin/`. Both trees are built (`AfterLogin` for desktop, `MobileAfterLogin` for the `.page-header` bar), plus the account dropdown behind the avatar. Sign in through the auth dialog and out again through the dropdown's Log Out row, which calls `signOut()`.

**Nothing here is inferred, and the reason is the method rather than the page** — the same story as `/vip-detail`. `AfterLogin-Xr01UEkM.js` and `index-C2VSp-Vh.js` were both on this file's "not in the mirror" list, and both came straight off `hash.game/assets/`, along with `notification-shell-BOaO8MP0.js`, `IconAdd-*.js` and the nine `Icon*.js` chunks the dropdown imports. So the class lists are the Solid templates' own and every icon in `icons.jsx` is the deploy's own file. Prefer this route; it is now three pages in a row that did not need a screenshot.

**The header row div is NOT shared between the two states on the original, and one class is why.** `Header-CTF5n6al.js`'s `de` and `AfterLogin-Xr01UEkM.js`'s `M1` are the same list except that the signed-out one carries **`overflow-hidden`** and the signed-in one does not. This build renders one div for both branches (`Header/index.jsx`), so it was carrying the signed-out clip into the signed-in state — and since the account dropdown is an `absolute top-full` child of that div, the whole 624px panel was clipped away by a 60px box. The avatar toggled, the markup mounted, nothing painted. The class is now gated on `session.login`; do not put it back unconditionally. Nothing in the signed-in row needs clipping — its content is 516px inside a container that is never narrower than 784, because below `lg` this tree does not render at all.

**The geometry checks out to the pixel.** Measured off the capture at dpr 1.25, search-left to avatar-right is 516px, and the class lists add to 40 + 12 + 264 + 12 + 40 + 12 + 80 + 12 + 44 = 516 exactly. The pill's 264 is `sm:w-[16.5rem]`, every 12 is an `ml-3`, and the coin, chevron and Deposit button all land where `.button`'s own 8px padding puts them.

**`w-30` is a dead class that this build cannot keep, and it is the one place Tailwind v4 diverges from the original by *adding* a rule.** The chunk classes the chat/bell group `clsx("... flex h-10 flex-none ...", isOfflineAgent ? "w-10" : "w-30")`, and `.w-30` is in none of the fourteen stylesheets this deploy ships — Tailwind v3's width scale has no 30, so the class resolves to nothing and the group is sized by its content at 80px, which is what the capture measures. Tailwind v4 generates the spacing scale on demand, so writing it emits 120px and the group renders 40px too wide. It is dropped, with the chunk's line quoted at the call site. **Every other dead class here is kept** — `header-nav-item` on the dropdown rows, `not-full` on the Deposit button, and `size-[26px] fill-secondary` on the two sprite icons (dead twice over: those elements are background-image `<div>`s, so `fill` does nothing, and unlayered `.color_icon_img` pins them to 32px regardless — 32 at `scale-[80%]` is 25.6, which is what "26px" was written to match). Note the generated `.w-30` still appears in the built CSS because Tailwind scans comments, including the one explaining why it was dropped; it is 40 unused bytes.

**The private-chat button is not rendered, and that is measured rather than chosen.** The chunk gates it behind a lazy chunk, and the divider beside it carries `first:left-10` — a `:first-child` variant, so the divider sits at 40px only when nothing precedes it and at `left-20` (80px) when the chat button does. The capture has it at 40px inside an 80px group. Two independent measurements, one answer.

**Chat and bell are the coloured SPRITE, not SVGs.** `Dh` and `un` in Enter both test `when: !1` and fall through to `<Icon name="chat"|"notice" select={false}/>`, so the SVG sitting beside each one never renders. `.color_icon_img.notice` is `-192px -96px`, added to `index.css` next to the `.chat` rule that was already there.

**The avatar's purple ring is the image, not a VIP frame.** `sE` wraps the avatar in a federated `Frame` keyed off `userAvatarFrameList`, and the fixture's list is empty (`t.id || -1` resolves to the original's own "no frame"). The ring samples `#8100F8` at the image's own edge, *inside* `p-[3px]` — it is part of the PNG. `105522617.png` is that exact avatar, already in this repo from the weekly-raffle winners, where it is the most common bc.game default.

**The dropdown panel's height is arithmetic, not layout**: `(rows + 1) * 44 + 8`, written onto the class list as `h-[NNNpx]`. 44 is `h-11`, 8 is `p-2`, and the `+ 1` is `DialogDisturbSetting`, the Do Not Disturb row — thirteen menu rows plus it gives the `h-[624px]` the rendered DOM carries. `fadeUp2` (`{opacity:0,y:16} -> {opacity:1,y:0}`, `duration .3, power2.out`) is in `AfterLogin.css` because a keyframe cannot be a utility; it is enter-only, since the panel unmounts rather than transitioning out.

**Every row carries `button-m` and every row icon carries `icon`, and neither is written by the call site on the original** — `ot` appends `button-${size}` with `s = size || !mobile && "m"`, and the icon wrapper (`d` in `Wrap-DblNcHvH.js`) prepends `icon` to whatever class it is handed. Both are inert here (`h-11` beats `.button-m`'s 2.5rem, its `--radius-lg` never shows because no row paints a background, and `.icon` is layered so `size-6`/`fill-secondary` beat it) and both are in the rendered DOM, so both are written.

### Do Not Disturb

The dropdown's last row — `src/layouts/MainLayout/Header/AfterLogin/DisturbSetting.jsx`. **It is not in `AfterLogin-Xr01UEkM.js` at all**: `Enter` resolves it through the `account` remote, whose `manifest-zssWG_dx.js` maps the expose to `Disturb-CUKXIk9c.js`, and the mirror saved that remote **without its lazy chunks**. So this is the Help Center's finding one directory up — the file came off `hash.game/modules/account/assets/`, it is 3.3 KB, and it holds the entire component including its icon inline. All three strings are verbatim en-US out of the remote's own locale bundle (`index-B9isM8z3.js`, which *is* in the mirror, where each maps to itself). Nothing on the row is inferred.

Four things about it:

- **The row itself does nothing.** Its `onClick` is `e => e.stopPropagation()` and nothing else, so the label and icon are inert and only the switch toggles — the stop is there to keep that click off the panel behind it. It is the only row whose handler is not the menu's `go(row)`.
- **The switch is a `<div>`, not a `<button>`.** `CO`'s own markup, and forced either way: it sits inside the row's `<button>`, where a nested button is invalid and undeliverable. `role="switch"` carries the semantics; `.switch`/`.switch-xs` were already in `index.css` from the currency dropdown's Hide Small toggle.
- **`max-sm:` with nothing after it is the original's own dead class**, out of a `clsx` handed an empty string — kept for the reason `f-ull` and `texxt-sm` are. The row's *live* `max-sm:` arms are unreachable here anyway: the dropdown is desktop-only.
- Turning it on the first time raises a confirm; the flag behind that lives in localStorage under `first-set-disturb-<userId>`, which is `makePersisted`'s key verbatim (`nv` uses `e.name` with no prefix). Cancelling leaves the flag set, so the next attempt asks again.

**The confirm dialog is the site's generic one** — `Pt.confirm` → `tS` inside `cl`, transcribed into `ConfirmDialog.jsx` over the `.pop-*` CSS that was already there. Three things it gets right that are easy to lose:

- **The backdrop does not close it.** `Pt.confirm` pushes with `{close: !1}` and the overlayer branches on that flag: `u.close ? Pt.pop() : c()`, where `c()` toggles **`head-shake`** on the topmost popup. A click outside shakes the dialog; a confirm has to be answered. The class and its keyframes are `index-DxOqNczA.css`'s and are in `AfterLogin.css`, below the enter animation — same specificity, both set `animation`, so source order is what keeps them from fighting.
- **The scrim and the panel are ONE gsap tween**, not two: `Qx` tweens a single value over `{duration: .35, ease: "power3.out"}` and two effects read it per frame, `rgba(16,18,18, v*.8)` on the scrim and `opacity: v; scale(v*.2+.8)` on the panel. Animating the container's opacity reproduces both halves off one clock. `power3.out` is GSAP's *quartic* ease-out — a different bezier from the dropdown's `power2.out`.
- **`useConfirm` is called in `AccountMenu`, not in the row, and that placement is load-bearing.** The original's popup lives in a global list at the app root, which is what keeps it alive when its opener goes away: clicking inside the dialog satisfies the dropdown's own click-outside, so the dropdown closes underneath it and the row unmounts mid-promise. Called from the row, the dialog would vanish on its own first click. The hook is in its own file for the reason `useSession` is not in `SessionContext.jsx` — `react-refresh` rejects a module exporting both a component and a hook.

Not built: the popup **stack**. `Pt` is a global list with a shared scrim, one tween per entry and a head-shake on the topmost; `useConfirm` renders one dialog from local state instead. Lift it to `components/shared` the day a second thing confirms — which is the same rule `Select` and `GameTile` were extracted under.

**Both arms of every `dark:` pair are written now — see the Light theme section.** This paragraph used to say the opposite, and the reason it gave was sound at the time: with no `.dark` class and no `@custom-variant`, a `dark:` utility resolved to `prefers-color-scheme` and would have handed a light-OS visitor `bg-alw_white`, a white pill on a dark page. The variant is class-keyed now, so the dropped light arms were restored at every call site that had recorded one in a comment. The pill above is worth reading anyway as the case where the two arms turn out to COINCIDE: `bg-alw_white dark:bg-layer3` against `bg-layer3` is the same colour in both themes, because light `--alw_white` and light `--layer3` are both pure white.

`utils/currency.js` is **`printCurrency` ported whole** — the first complete copy; `Contest` and `Referral` each carry a partial one for their own two branches and were left alone. Four things it gets right that are easy to miss: the second argument is the SOURCE currency while `target` comes from `enableLocaleCurrency`; the fiat branch deliberately does not pin `maximumFractionDigits` (and node's ICU disagrees with Chrome about IDR — trust the browser); `hasAlias` defaults true, so crypto carries its ticker; and `roundingMode: "trunc"` throughout. `dd`, the compact-notation splitter, is verbatim including its unit table — its threshold is the *precision*, so nothing compacts below 10^8 and 1,250,000 prints in full rather than as "1.25M".

**`enableLocaleCurrency` is ON, and the pill prints a converted dollar figure.** The capture pairs a BCD coin with "$0.00", which only happens with that switch on and `localeCurrencyName` at USDFIAT — the coin comes off the wallet's own currency while the figure is converted for display. It sat off for a while because converting needs an FX rate, and `convert()` in `utils/currency.js` was a documented no-op. **`src/data/usdPrice.js` closed that**: `hash.game/api/game/support/system/conf/usdPrice` is the path the bundle itself names and it answers unauthenticated, so `convert`/`amount2usd` are the real thing now and the pill reads `$128.40` over its BCD coin. Two things about that table — the fetch hook **overwrites** `USD` and `USDFIAT` to exactly 1 after fetching (the response quotes USDFIAT at 1.00094, and USD is not in it at all, yet it is `convertCurrency`'s default target), and every crypto row is a **spot price frozen on the day it was pulled**, which is the one kind of staleness that is invisible on screen. `SIGNED_IN.setting.currencyName` was moved from the defaults' BTC to BCD, which is the account's own `bonusCurrencyName`.

### The currency dropdown

What clicking the wallet pill opens — `Header/AfterLogin/CurrencySelect.jsx`. **The whole pill is the trigger**, not the coin or the chevron (`Qe` passes that div as the popover's children), which is why the Deposit button has to `stopPropagation` to stay a Deposit button. Built from the real chunks again: `index-C2VSp-Vh.js` names its layer as a lazy import of **`SelectLayer-CwsGOFvY.js`**, and that came off `hash.game/assets/` like the rest.

**The panel is a sibling of the pill in the React tree, and that is a constraint rather than a preference.** It portals itself to `<body>`, but a portal still bubbles its events through the *React* tree — mounted inside the pill, every click on a coin row also reaches the pill's own toggle and reopens what it just closed. Same trap for anything else portalled out of a clickable box.

**The data was the missing half, and both halves of it are now real.** The chunk carries markup, not coins:

- **`src/data/currencies.js` is GENERATED from a live answer** — `hash.game/api/game/support/system/conf/index/minimal`, field `currencyV2`, 324 rows. That is `fo.currency`, the store `getCurrency` reads, and it settles `currencyType` (what the panel groups on) and `fullName` (what its search matches besides the ticker). **The alias is not cosmetic**: KLAY prints KAIA, TON prints GRAM, TOMO prints VIC, UST prints USTC, and the coin image is fetched under the alias too. `getAlias` in `utils/currency.js` was `currency.replace(/FIAT$/,'')` and is now the lookup the original actually performs; `toFiatStr` keeps the strip, because Intl wants the ISO code and the two stopped being the same function.
- **The wallet's own list is captured, and it is two lists** — `/user/amount/` returns a row for every currency the account *can* hold and a `display` flag decides which the dropdown lists, so `context/account.js` carries `CRYPTO_ROWS` (89, read off the dropdown) and `FIAT_ROWS` (59: the first nine read off the Manage Assets sheet, which is the only place a hidden row is ever visible, plus the other fifty from the live catalogue). Order is the wallet's (`sortBy(store, "sort")`), **not** `currencyV2`'s catalogue sort — whose value is 1 for nearly every row and orders nothing — so `sort` is simply the array index and reordering the arrays is what reorders both panels. **The two lists are concatenated and the join is arbitrary on purpose**: the real wallet interleaves them under one `sort`, but both consumers group by currency type *before* they read it, so no comparison ever crosses the join. Every amount is invented and only BCD is non-zero. The evidence stops after the ninth fiat row; everything past it is in catalogue order, and the crypto tail (162 more coins) is deliberately not added rather than filled with 162 rows in an order known to be wrong.
- **All 148 coin icons are local**, pulled from `imgxcut.com/coin/<alias>.<black|rect>.png` (`YC` in index-BsFv7ByC.js builds that URL) and saved under `currencyName`, which is the key everything looks a coin up by. `utils/coinArt.js` is the shared glob; the four older per-file copies were left alone.

**`displayStatus: 1` on INRFIAT is the one field that looks arbitrary and is not** — though note the fixture no longer sets it on any row; see the shown-fiats note under Wallet for why. It is the only mechanism in the chunk that survives Hide Small at a zero balance — everything else has to clear $0.10 through `convertCurrency` — and it is why the capture still lists Cash / INR with that switch on while the other 88 empty rows go. The original stamps the same 1 on any coin you pick out of a search, so it does not vanish again when the search clears.

**A row's height is decided by `enableLocaleCurrency`, not by CSS.** With it on, the amount column is the converted figure over the raw one in `.text-second` — two lines at `!leading-5` inside `py-3`, so 64px — where a single-line row is 48. If the rows ever look short, check the switch before reaching for the padding. A fiat row is single-line either way (`isFiat` returns before the second line), so Cash / INR really is shorter than the crypto rows below it.

**Four dead classes are kept and one of them is a trap.** `scroll-target` on the selected row and `light-darkness` on the `+` button paint through `.app-root:not(.dark)` — a **light-theme-only** rule, so both are inert here and `bg-layer4` is what actually lights the selected row. `search-input` and `list-title` generate nothing at all. What *is* live is `.fix-light-hover`'s hover/active pair, a 3% white `background-image` over whatever `hover:bg-layer4` puts in `background-color`; it is in `index.css` behind the original's own `(hover:hover) and (pointer:fine) and (min-width:640px)` guard.

**`.currency-select .icon` is UNLAYERED, and that is the cascade hazard in its usual direction.** The BCD/BC rows' `(i)` link is `<IconInform class="size-4"/>`, so both rules apply to it; on the original — Tailwind v3, no layers — specificity settles it 0,2,0 to 0,1,0 and the icon renders at 20px. Inside `@layer components` the utilities layer would win outright and it would render at 16.

**The spinner on first open is staged, and it is the only invented timing in the project.** Two things gate the panel on the original and both are network: `SelectLayer-CwsGOFvY.js` is a lazy chunk the pill imports the first time you click it, and `Jt` then holds the content behind `<Show when={currencyStore.init}>`. So the first open spins and every open after it does not. Here the catalogue is a module constant, so `LAYER_LOAD_MS` (300ms, once per page load, behind a module flag rather than state) stands in for the fetch. Set it to 0 to remove the whole thing.

Three more things worth knowing. The **tab strip is rendered `hidden`**, exactly as the capture has it: `Jt` only unhides it when some coin carries a sports or free-play balance and none does, so the Bonus Balance panel behind it is unreachable and is not built. The **panel is a separate component from the popover shell** so that closing unmounts it and the search box resets — the original mounts it lazily inside `<Show when={visible}>`, and clearing the field on close instead would be a setState in an effect. And `-mx-4` on the sticky footer **overshoots the layer's 8px gutter by 8px a side on purpose**: `.scroll-y` clips it, so the bar bleeds to the layer's edges. Do not "fix" it to `-mx-2`.

Not built inside the panel, each inert at its call site rather than removed: "View in currency" (which emits `open-fiat` and is what turns `enableLocaleCurrency` on), the unsettled-bets banner (`/platform-japarot/user-provider-balance-list/`, no captured response), and the Swap Coin button in the not-found state.

**The bottom-sheet arm IS built now**, and it belongs to `Select` rather than to this panel — see Bottom sheets below.

### The language / currency picker, and which trigger gets which panel

**There are THREE popups, not one, and the split is by TRIGGER rather than by width.** `Enter-MsmOuq5R.js` registers all three and that is where an earlier reading of this went wrong — it is where they are *handled*, not where they are *emitted*. Grepping the mirror for the emitters settles it:

| event | emitted by | panel |
| --- | --- | --- |
| `open-lanfiat` | `Header-CTF5n6al.js`, `index-DuwOs_Mv.js` | **combined**, a tab strip for its title |
| `open-language` | the account remote (`index-BgFc4GKH.js`, `Enter-LgsyJFjc.js`) | single, plain centred title "Language" |
| `open-fiat` | the same two, and the currency dropdown's own row | single, "View in currency" |

So **the header and the sidebar open the combined panel** — the header's language button is `g.emit("open-lanfiat", 0)` and its currency pill `("open-lanfiat", 1)`; the sidebar's two rows are the same pair — while **Settings → Preferences and `/user/enter` open the single-purpose ones**. The argument is the STARTING TAB, not a different dialog, which is what `initialTab` carries in `components/modals/LanguageCurrencyModal`; `merged` is what picks between the two shapes.

The strip is the popup's `title`, a `type="indicator"` tabs row with `divider`, and its second tab is `<Show when={!Pe.isFiat}>` — the deploy flag `App.jsx` already records as never firing here, so both tabs always render. **The panel's own class list was already sized for it** (`pt-16 sm:pt-14`, `[&_.pop-title]:h-14`, `[&_.pop-close]:top-4`): those were tuned when the strip last existed and left in place when it was removed, and the note at `.pop-title` in `index.css` records exactly what breaks when they are wrong. Switching tabs clears the search, because on the original the two panels are separate components that unmount each other and this build renders both lists from one query.

### Bottom sheets

`js`, the shell both dropdowns share, ends with one decision: `const u = L(() => t.dropdownType ? t.dropdownType === "pop" : ee.mobile)`. True renders `CS`, false renders `wS` — the positioned `.dropdown-layer` this build had. `CS` is three lines: push `cl` with `class="min-h-52 select-options"` and `title = t.title || "Select"`. **`cl` is `components/shared/PopCenter`**, whose own sheet arm had stood unreachable because nothing passed a `type`. So below `lg` every Select opens from the bottom of the screen.

Four things the source settles that a screenshot cannot:

- **The title bar's CONTENTS branch, not just its position.** `cl` renders title-plus-close-square on a desktop and template `Kx` on a phone — `<div class="w-11 h-1 rounded-sm bg-layer6 mx-auto mb-2.5">` over `<div class="text-center">`, with **no close button at all**.
- **The scrim closes on CLICK, not pointerdown** — `qe(o, "click", l => { if (l.target !== o) return; … })`. Not stylistic: the scrim covers the trigger that opened the dialog, so closing on pointerdown unmounts it between mousedown and mouseup and the click lands on whatever is underneath. For a dropdown that is the trigger, whose handler toggles, so tapping it closed the sheet and immediately reopened it. Every dialog in the build now takes the click form.
- **The sheet slides and the centred card scales**, off the same clock. The manager tweens one 0→1 value at `duration: .35, ease: "power3.out"` and picks the animation by reading the class off the element: `!n.classList.contains("pop-center")` gives `translate3d(0, (1-i)*100%, 0)`, otherwise `opacity: i; scale(i*.2+.8)`. That is the same value the scrim's `rgba(16,18,18, i*.8)` reads, which is why the two cannot drift. Reproduced as a keyframe; enter-only, since the exit half needs the popup stack.
- **Drag-to-dismiss is `Vx`**, and its four load-bearing parts are ported: the nearest scrollable ancestor decides whether a downward swipe is a drag at all (only within 16px of that scroller's top — without it a sheet holding a long list can never be scrolled), pulling up resists on an asymptote that approaches the sheet's own height, dismissal is velocity **or** distance (`b > .3 || c() > a/2`, so a short flick counts), and the other arm snaps back on the same 0.35s tween. Not ported: `Vx`'s horizontal arm bound to `document`, which is the router's edge-swipe rather than the sheet's.

**`PopCenter`'s default is still the centred card**, where the original's is the sheet — `t.type` undefined means sheet there, so the deposit-offer detail dialog, the 7-Day explainer and Manage Assets would all be sheets on a phone. Inverting it is one word (`type !== 'center'`), left alone only because those three have not been looked at below `lg`.

### Manage Assets

The sheet behind the `+` beside the dropdown's search box — `yt` in the same chunk, `ManageAssets.jsx`. Crypto and Fiat tabs over one switch per coin, and **that switch IS the `display` flag the dropdown filters on**, so turning one off removes the row from the wallet pill's list and turning it on puts it back. It rides the `.pop-center` shell (`cl`) the deposit-offer and region-block dialogs already use, and unlike the deposit-offer one it *shows* that title bar, close square and all.

Three things about how it is wired. It is pushed imperatively (`re.push(yt)`), and the `+` **closes the dropdown before pushing it** — so its state lives on the wallet pill rather than inside `CurrencySelect`, which is unmounted by then. It is **portalled to `<body>`** where the deposit-offer dialog renders in place: `.pop-overlayer`'s `z-index: 1100` resolves against the nearest stacking context, and mounted inside the fixed, z-indexed header it would otherwise be trapped under it. And the search is **debounced 300ms** (`De(r => Ge(r, 300))`) where the dropdown's is live — worth keeping, since this list is 148 rows.

Its filter matches on `currencyName` and `fullName` and **not on the alias**, which is a real difference from the dropdown's own filter one file over: searching "kaia" finds nothing here and finds KLAY there. Both are transcribed as written.

**Building it is what exposed a bug in the dropdown**: `CurrencySelect` was grouping the whole wallet rather than `partition(coins, d => d.display)`'s displayed half. That was invisible while every fixture row was displayed and stopped being invisible the moment 58 fiats were switched off — they all turned up under Cash. The hidden half has exactly one home, and only while you are typing: the `HIDE` group, "Other Supported Coin(Click to add and use Coins)", which is how you turn a coin back on without opening this sheet at all.

**The scrim moved onto `.pop-overlayer`**, which is where the original puts it — not in its stylesheet, but written inline by the popup manager onto *every* overlayer it creates (`o.style.backgroundColor = rgba(16, 18, 18, a() * .8)`, tweened 0→1 over 0.35s with easeOutQuart). Because it was inline there was nothing to transcribe, so four dialogs had each arrived at the same value separately — `.deposit-offer-scrim`, `.after-login-pop-scrim`, `.region-block-overlay` and an inline style on the language panel. All four declare exactly `rgba(16,18,18,0.8)`, so the shared rule changes nothing for them and they are now redundant; clearing them out is a separate pass. The fade animates the **colour** from zero alpha rather than the element's `opacity`, because the panel is a child of the overlayer and fading opacity would take the dialog with it.

Not reproduced: `re.push(yt).then(() => mobile && onReopen?.())`, which reopens the dropdown underneath once the sheet is dismissed — but only on a phone, and only the dropdown's desktop arm is built.

**THE GIFT NAVIGATES TO `/bonus`, AND THAT IS THE ORIGINAL'S OWN ARM RATHER THAN A DEPARTURE — reading the chunk is what settled it.** `notification-shell-BOaO8MP0.js` (off `hash.game/assets/`, not in the mirror) is BOTH headers' gift: the desktop tree and `Cs` each insert the identical `Suspense(BonusNotifications)` into a Button that carries **no handler of its own**, and the click lives inside on an `absolute inset-0` div that fills that button and doubles as the dropdown's trigger ref. Its handler is `u() === 0 ? navigate("/bonus") : setShowNotification(v => !v)` — so the panel is what a click opens only when something is claimable, and otherwise the gift is a link to the Bonus page. `u` is its **own** reduce over the `/activity/bonus/v2/` payload (`Object.values(rewards).flat().reduce((o, n) => o + (n.canClaim ? n.items.length : 0), 0)`) and **not** the payload's `unclaimedCount`, which only the panel's Claim All button consults. Every entry in this build's payload is `rewards-service-CxFWsPYn.js`'s own `initialValue` — `canClaim: false` over empty `items` — so the count is 0, the navigation is what a click does, and the panel is unreachable. The count is read off that feed rather than hardcoded, which is the arrangement `FreePlayDot` has with the Free Plays dialog: one resource, so a badge and the thing it counts cannot disagree. Two consequences of reproducing the structure as written — the dot slot renders nothing, which was already right and is now right for a known reason, and the hit target is the div rather than the `<button>`, so a keyboard activation does not reach it on the live site either.

**THE GIFT'S DROPDOWN PANEL IS BUILT** — `yt`, in `AfterLogin/BonusPanel.jsx`, off the same recovered chunk. Three blocks in one `bonus-scope` column: a sticky header carrying Total Claimable and Claim All, one row per claimable ITEM between them, and a sticky "View All Bonuses ›" footer. Both sticky bars are `bg-layer1`, which is why the layer paints layer1 on a desktop and **nothing at all** on a phone — the bars supply the fill and the panel's own wrapper adds the rounding. Three things the shell does by hand rather than leaving to the Dropdown it renders, and all three are reproduced: the popover is handed `setVisible: () => {}`, a deliberate no-op, so **a CAPTURE-phase listener on `document` owns the closing** — capture rather than bubble, because a row inside the layer stops propagation and a bubble listener would never see the clicks it is meant to ignore; `lock-scroll` goes on `<body>` on a phone only and comes off on unmount either way; and the layer's geometry is the chunk's own, `!w-screen` under `sm` against `sm:!w-[26rem]`, `max-h-[21rem]`, 16px from the trigger on a phone and 30 on a desktop, and z-index **98 below the header and 1001 above it**, which is not a typo. Its money is `components/shared/BonusCurrencyAmount`, which is NOT `CurrencyAmount`: that one is a coin mark beside a figure, this one is the figure alone SPLIT into prefix / digits / suffix so the digits can truncate while a symbol or a ticker stays legible — precision decided by the TARGET currency, truncation throughout, and `< 0.0000001` for a non-zero amount that truncates away. Its ResizeObserver-driven tooltip is the one part not ported, this build having no tooltip primitive.

Not built around it: the gift's `track` event and the claimable-item detail flow a row opens, Claim All's write (which stops at the original's own `unclaimedCount === 0` gate); the global chat drawer `onToggleChat` is the seam for; and `/notification`, the one route the dropdown points at that still falls through to the catch-all. `/settings` came off that list — see Global Settings. `/user/profile/:id` is off that list — see My Profile, which is three dialogs deep. `/wallet/*` is no longer one of them — see below, and neither is `/user/enter`, the phone's stand-in for this whole dropdown — see Mobile account page. `/free-plays` is off the list too — see Free Plays, which also settles `FreePlayDot`: its chunk is recovered, it reads the same resource the dialog does, and at `totalCount` 0 the correct rendering is the empty slot that is already there.


## Mobile account page

`/user/enter` — what the mobile header's avatar navigates to, and the phone's answer to the desktop account dropdown. There is no dropdown below `lg` and no page above it; the two are alternatives, not a responsive pair.

**It is a DIALOG ROUTE with two guards and both are reproduced**, in `App.jsx` where the path is matched rather than inside the page:

```
{ path: "/user/enter", component: w("DialogUserEnter"),
  info: { guards: [() => !m.mobile && "/"], dialog: { behavior: "transparent-title" } } }
```

inside a group carrying `{dialog: !0, guards: [ce]}`. The route's own guard sends a desktop to `/` (read as the 1024 line, as everywhere); `ce` is `authGuard`, `!login && "/login/signin?redirect=…"`, so a logged-out visitor gets the **sign-in** dialog — the same shape `/deposit` takes one line up, whose guard names the sign-up tab instead. The `?redirect=` round-trip is not reproduced, since `signIn()` here swaps a fixture rather than routing.

**Nothing on this page is read off a screenshot, and the route to that is the Help Center's finding one directory up.** `DialogUserEnter` is federated: `Enter-MsmOuq5R.js` resolves it through the **`account` remote**, whose `manifest-zssWG_dx.js` maps the expose to `Enter-LgsyJFjc.js`. The mirror saved that remote without its lazy chunks, so the file (62 KB) came off `hash.game/modules/account/assets/` along with `Tool-iuNkSQmo.js`, `CopyInput-B_53zFi6.js`, `Signout-CdJMMBfB.js`, `Status-DpPfKxTy.js`, three icon chunks and the page's own stylesheet `Enter-CtHSAdBf.css`. Every class list below is the Solid template's own and every string is verbatim `t("…")`.

**`transparent-title` is a real behaviour and it is what forced the rest of the dialog shell out into `components/shared/RouteDialog`.** That component is the full-screen arm of `info.dialog` — portal, title bar, back arrow, scroll lock, Escape — and it has two consumers now, this page and `/wallet/withdraw`; `/deposit` predates it and still writes its own, because it renders a desktop card as well and that arm is not modelled. **The title bar's CONTENTS branch on device, not just its style**: `FS` gives a phone a back arrow on the left and *no close square at all*, where a desktop gets the cross and only shows the arrow when it is not the first dialog on the stack. Only the phone arm is drawn.

Three rules come with `transparent-title` — `dialog-transparent-title` on the item, a title bar that is `position: absolute` rather than a flex row, and a background on that bar whose alpha is driven by scroll:

```css
.dialog-title { --tw-bg-opacity: calc((var(--scroll) * 100 / 15) - 50%);
                --bg: var(--layer4); background-color: rgb(var(--bg) / var(--tw-bg-opacity)) }
```

with `--scroll` written onto `.dialog-overlayer` as a **percentage** (`100 * scrollTop / innerHeight`). `_()` starts at 100 and is only ever recomputed for a transparent bar, which is why an ordinary dialog's is opaque from the first frame; a transparent one is clear until the content has moved 7.5% of a viewport and opaque at 22.5% of one, the `-50%` term producing the negative alpha that clamps to zero over the first stretch. **All of it is scoped to `.route-dialog` rather than written bare in `Auth.css` beside the rest of the shell**, and that is not tidiness: the auth dialog carries `dialog-transparent-title` too, paired with `dialog-no-title`. It survives on the live site because `--safe-header` is genuinely declared there; this build deliberately leaves it undeclared (see the `--spacing-sh` note under VIP Club), so bare rules would resolve against a `0px` fallback and quietly move the auth dialog's content.

**`--safe-top` is this build's own value and it is the requested "top gap".** On the live site it is the device's top inset, written from `env(safe-area-inset-top)` — zero in a desktop browser and zero in responsive mode, which is why the bar sat flush against the top edge. It is a flat `1rem` on `.route-dialog`, and it flows through the site's own arithmetic rather than being a one-off margin: `--safe-header` is `calc(3.5rem + var(--safe-top))`, the title bar takes the inset as `border-top` under `box-sizing: content-box` so the bar grows instead of its contents shifting, and the scroll container takes the total. Both variables are declared on the LIST, not on `:root`, so `.dialog-item` in `Auth.css` goes on rendering its own `0px` fallback. **The back arrow is the original's DESKTOP pair on a phone bar** — 1.5rem around 0.875rem at `bottom: 1rem`, where `.appbar .dialog-back` would be 2rem around 1.25rem; a requested departure, and both numbers move together because the smaller box ships with the larger `bottom`.

Six blocks under the header, and four things about them are worth knowing:

- **The XP line is on the PROGRESS ROW, not under the tier name.** `t(u, <Show …/>, null)` appends it to the `mt-3 flex h-5 w-full items-center` div, so the bar takes `flex-1` and "1.00K XP to BRONZE I" sits beside it. Its formatter is `S1` out of `Tool-iuNkSQmo.js` and is **not** the bonus page's `compactXp` — this one pins two decimals at every magnitude, which is the whole of why the capture reads 1.00K and not 1K.
- **The card's gradient is picked by TIER NUMBER, not by level.** `vipTypeNum` is new in `data/vipConfig.js` and it is `j1`, a 34-entry lookup collapsing the ladder onto 0..8 — Platinum spans two numbers, Diamond three, and 6 is also the `isSvip` line. The nine `user-vip-N-*` sets in `Enter-CtHSAdBf.css` are indexed by it, which is why they stop at 8. Their `-light` twins are deliberately absent, as `banner_bg_w` is on the VIP page.
- **A button on this page gets NO size class, and that is `ot`'s own rule.** `s = size || !mobile && "m"`, so on a phone — the only place this page renders — every button that does not name a size gets none. The eight wallet tiles are that case; Deposit and Withdraw pass `size: "m"` explicitly and do carry `button-m`.
- **`h-22` ON THE PROFILE HEADER'S INNER BOX IS A DEAD CLASS AND CANNOT BE KEPT — the `w-30` trap a third time**, and it is the one class of bug where Tailwind v4 diverges from the original by *adding* a rule rather than missing one. The chunk writes that box `h-22 absolute bottom-0 z-[1] w-full`, and `.h-22` is in none of the stylesheets this deploy ships: v3's height scale steps 20 → 24, and the account remote's own sheet carries `.h-20`, `.h-24`, `.h-25` and `.h-28` but no 22. So the box is AUTO height on the live site — exactly its `h-16` child, 64px — which pins the avatar row flush to the header's bottom edge. Writing it here emitted 88px and pushed the whole row 24px up off that edge, which read as an oversized gap between the avatar and the VIP card and was chased twice as spacing before the class was checked. **Check any `h-*` or `w-*` outside v3's scale against the deploy's CSS before transcribing it**; `h-18` on the wallet is the counter-example, a step that really is there.
- **The community squares are NOT `components/shared/CommunityItem`.** That component is `CommunityItem-DguQXLpB.js`, a `btn-like … rounded-lg` button in `text-secondary` shared by the footer and the sidebar card; this list is written inline in the account chunk as `center h-10 w-10 rounded-md bg-layer3` with no text colour, so its marks take the page's white. Different radius, different colour, different file — only the eight-entry `Kk` data is shared.

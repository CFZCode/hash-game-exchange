# Project overview, the recovery ladder, Sports, and the loose ends

Part of the bc.game rebuild notes. Index and cross-cutting rules: [../CLAUDE.md](../CLAUDE.md).

## What this project is

A React + Vite rebuild of the bc.game front-end UI, built to match the original layout at the pixel level across every breakpoint. The work is primarily CSS/markup fidelity and faithful *mechanism*, not application logic. **There is a data layer now** — every payload goes through `src/services/` behind one seam, and none of it reaches a backend: see The data layer below, which is the section to read before writing a fixture.

State in `src/context/`, plus routing:

- **Session** (`SessionContext.jsx`, `session.js`, `account.js`, `persist.js`). Stands in for the original's persisted `account` store (`NC` in `index-BsFv7ByC.js`). The shape is that store's own literal; the values are the mirror's captured `/account/get/` and `/user/amount/` responses. `signIn()` swaps to a second, **invented** fixture — the mirror was captured logged out, so no real signed-in response exists to copy. Read it with `useSession()` from `context/session`, never from `SessionContext.jsx` (Fast Refresh forbids a file exporting both a component and a hook).

  **It survives a reload, and WHAT is stored is the whole design.** `persist.js` is `nl` ported — `localStorage["account"]`, the original's own key. Storing the account object *whole*, as the original does, would mean every edit to `SIGNED_IN` silently doing nothing until you cleared your browser, which is exactly why this was left unpersisted for a long time. So the record holds only what a visitor can actually change — `login`, `name`, and `setting` (the wallet's selected currency and Hide Small) — and everything else is rebuilt from the fixture on load, with `setting` merged *over* the fixture's so a key added later still appears. The gate against stale records is the original's own trick and worth keeping: the record carries a **hash of `ACCOUNT_DEFAULTS`**, so changing that shape discards every saved copy with no version number to remember to bump. Two things deliberately do not survive: the wallet's per-coin `display`/`displayStatus` flags (server state on the live site, and faking it locally would be inventing a server), and nothing at all if `localStorage` throws — private windows and disabled site data are caught and ignored, because a header that cannot render is worse than a sign-in that does not stick. Sign-out writes `login: false` rather than deleting the record, as `nl` does.
- **Settings** (`settings.js`, `SettingsContext.jsx`) — the theme, over the same `persist.js`. The state is `theme` and the boolean is `darken`; see Light theme below, and note two separate controls write it and neither owns it.
- **Wallet filters** (`walletFilter.js`, `WalletFilterProvider.jsx`) — the type/status/time/currency set the transaction, rollover and bet-history panes share, seeded from the URL then `sessionStorage`.
- **Routing** (`react-router-dom`, mounted in `main.jsx` so the chrome can read the location). `/` and `/casino` are the original's own pair — the list `ks()` tests before letting the mobile header fade with scroll — though `/casino` has had its own page since, so only the catch-all renders Home now. It still does so deliberately rather than 404ing; the reasoning and the full route list are under Routes below.

The **auth dialog** (`src/components/modals/Auth/`) is route-driven, because it is on the original: the header's buttons navigate to `/login/signin` and `/login/regist`, and `App` matches the path and renders the dialog *over* the page rather than inside `<Routes>`. Its Sign In markup is transcribed from the live rendered DOM; the One-time Code and Sign Up tabs are built from the same primitives against screenshots. A valid submit calls `signIn()` — there is nothing to authenticate against.

**THE DIALOG'S CHUNKS DO EXIST — in the `account` federated remote, not in `/assets/`.** The manifest (`hash.game/modules/account/assets/manifest-zssWG_dx.js`) maps `DialogSignIn` → `index-BBR8C42e.js`, `DialogSignUp` → `index-DBnPZihO.js` → `Enter-S9f2xlL8.js`, and `DialogSignin2FA` → `Login-DOwjxTVG.js` (export `S`; the in-dialog step is `xr`/`pr` beside it). Two pieces are built from them so far. **The 2FA step**: a pop pushed over the dialog with `{close: false}` (so the scrim head-shakes), a three-tab `special-tabs-change` strip with no titles and no CSS — drawn as the host Tabs renders it — over the Authenticator mark, Verification Code, `PasteInput`, an inert `Tip2FA` and Confirm. SmartBet has no `verifyFlowId`: the login answers `AUTH_TWO_FACTOR_REQUIRED` and the code goes back on the same `POST /user/auth/login` as `twoFactorCode`. A wrong code prints the server's message in the sign-in slot's markup under the field, where the original toasts. **The Sign Up error slot**: `Enter`'s own `<p class="mt-1 text-xs text-error">` directly after the email field, `border-error` on the box, cleared on focus; a 422 prints `details.fields[0].message`. The rest of both forms is still the live-DOM transcription and was not re-checked against these chunks.

**IT OPENS AND CLOSES WITH THE MANAGER'S OWN MOTION NOW, AND IT IS THE FIRST SHELL HERE THAT HAS TO PICK THE ARM AT RUNTIME.** `N()` in `index-BsFv7ByC.js` animates the scrim (`.dialog-root`, `#0000` → `#000a`) and the card (`.dialog-list`, `scale(.92)`/`opacity 0` → `scale(1)`/`opacity 1`) over one 300ms `cubic-bezier(.36,.66,.04,1)`, and **the close is those same keyframes reversed** — `O.animate(H ? se : se.reverse(), de)`, with `.dialog-visible` taken off only when the scrim's animation *finishes*, which is what keeps the card painted for the full 300ms. **Both are skipped on a phone**: `ae = ee.mobile` hands the scrim two identical keyframes (`[Qu[0], Qu[0]]`) and guards the card animate with `if (!ae)`, so a phone gets `BS`'s slide and nothing else — in, and out through `a(S)`'s `R()`, which is `c(S,1,0)`, i.e. `translateX(0)` → `translateX(100%)`. **So `dialog-slide-out` in `DialogShell.css` is the manager's own gesture and not this build's invention**, which that file used to claim; only the dialog-to-dialog `-17%` arm (`k()`) genuinely needs the popup stack. Every other dialog here is still enter-only.

Two things that arrangement forces, both at the call site rather than in the CSS. **The close handler has to own the ORDER** — this build mounts a dialog off the pathname, so a handler that navigates first leaves nothing to animate; `runClose` raises a `leaving` flag, lets the reverse keyframes run and fires the real handler on a **timer** (an `animationend` listener never resolves under the reduced-motion arm, which shortens the animation to 0.01ms). **And `signIn()` has to move inside that timer**, not stay in front of it: it is what makes `depositNeedsAuth` and its three siblings false in `App`, so calling it up front unmounts the dialog mid-tween and the cleanup then drops the queued navigation with it — the dialog vanishes and the route never moves. `enter` is threaded down from `App` like every other dialog's, because it is a property of the transition and not of the dialog.

The **Explore panel** (`src/components/Explore/`) is what the desktop header's search button opens — `ae` in `Header-CTF5n6al.js` does nothing but `setExplore(true)`. Unlike the auth dialog it is **not** a route on desktop: `MainLayout` owns the `exploreOpen` signal (as Enter's root does), the panel portals itself to `<body>` as `.explore-pop`, and the body carries `explore-open`/`explore-close`, which is the only thing giving that fixed 0×0 container a size. Below `sm` the original has no overlay at all — Explore is the `/explore` route there, guarded to mobile and reached from the tabbar — so `Explore.css` keeps the rules inside the same `@media (min-width: 640px)`. The tabbar's Explore button navigates to that route now (it was inert for a long time, and this file used to say so).

One word to revisit, but it is not the fix for anything inside the pill.

The Explore search bar's type dropdown takes `size="s"` with `-my-1.5 … h-11`, which is the chunk's own pair.
- Sports and Lottery stay in the type dropdown (the captured `/sport/provider/support/` response carries a `betByBrand.brandFlag`, so the live session had all three) but render the empty state — neither feed was captured.

Shared primitives that used to live in component files now sit in `index.css`, and **which side of `@layer components` each one lands on is load-bearing in both directions**:

- *Layered* (`.button`, `.input`, `.button-l`, the whole `.tabs-*` family, and — added with Explore — `.select`/`.select-item`/`.radio`/`.dropdown-layer`) because call sites override them with utilities: `bg-input_darken` on `.input`, `bg-transparent` on `.tabs-content`, `border-none bg-transparent px-0` on the Explore search bar's type dropdown. Unlayered, the rule would beat the utility.
- *Unlayered* (`.hide-scroll`, `.hidden-scroll-bar`, `.smooth-scroll`, and the `.grid-col-2`/`.grid-col-3` presets, all moved out of `GameSection.css`) because they must beat utilities. `.grid-col-3 > div > *` sets `position: absolute; inset: 0` on a game tile, and every tile's class list carries Tailwind's `relative` — straight off the original. Putting that block in a layer let `relative` win, the tile fell out from over its 133%-padding spacer div, and every row of games on both the home page and the Explore grid rendered about twice as tall as it should. It was moved in and moved straight back out; do not repeat that.

See the cascade hazard below — it cuts both ways.

Two components came out of pages for the same reason: `components/shared/GameTile` (the 3:4 card, `io` — the home carousel and the Explore grid render the identical tile, including its `Math.min(index, 11) * 15ms` mount stagger) and `components/shared/Select` (`nO` and `FA`, the site's Select and MultiSelect — a `.button.select` trigger plus a portalled `.dropdown-layer` positioned from JS). `utils/gameArt.js` holds the artwork glob, because `import.meta.glob` resolves relative to its own file and so can only live in one module.

**`components/shared/Skeleton`** is the third, and it is the site's own — `v` in `skeleton-9E-gKDFG.js`, a lazy chunk off `hash.game`, over the `.skeleton` rules in `index-DxOqNczA.css`. The thing to understand about it is that **it wraps the real content rather than replacing it**: `::before` paints layer4 over the children and `::after` paints layer5 on top and pulses, so the placeholder is automatically the exact size and shape of what is coming and nothing reflows when the data lands. That is also why `visible` defaults to *true* — a call site turns it off, it does not turn it on. Two adaptations are recorded in the CSS: the fills name `--color-layer4`/`--color-layer5` because this project's `@theme` carries only the hex form of those tokens, and the original's dead second `transform` (Tailwind v3's variable chain, which overwrites its own `translateZ(0)`) is not reproduced.

Two call sites and **both render now.** `GameSection` draws eight placeholder cards when `games` is `undefined`, which is `useResource`'s pending state; that used to be unreachable because `services/client.js` answered fixtures synchronously, and it is reachable because that file no longer does — see Loading states below. The other is **`GameTile`, where the skeleton covers the cover until the image loads**, and that is this build's departure rather than the original's: on a reload the only thing genuinely still arriving is the artwork, ~120 covers of it. `complete` is checked in a ref callback as well as `onLoad`, because `load` does not bubble and a cached image can finish before React has wired the handler up — without that, a cached tile pulses forever.

**A skeleton must not be a `.grid-col-3 > div`'s direct child.** That rule stretches a tile over its spacer with `position: absolute; inset: 0`; `.skeleton` declares `position: relative`; both are unlayered at equal specificity and `.skeleton` is later in `index.css`, so it wins and the placeholder collapses to nothing. `GameSection` puts a plain div in between. Same family of trap as the one the cascade note describes.

**Not everything is in the mirror, but almost all of it is still reachable — read this before transcribing anything off a screenshot.** Chunks that were lazily loaded and never saved include the footer (`footer-jnUVITid.js`) and the sign-in/sign-up dialog (not in `/assets/` — it is in the `account` remote, see the auth dialog note above; `Entry-*.js` is unrelated glue). Several pages here were rebuilt from rendered DOM because of that. The desktop logged-in header (`AfterLogin-Xr01UEkM.js`) and the wallet pill (`index-C2VSp-Vh.js`) used to be on that list and are now **built from the real chunks** — see Signed-in header below.

They did not have to be. **The deploy is served from a second origin, `hash.game`, and that one answers when `bc.game` times out.** The VIP page's own `<video poster>` is what gave it away — it points at `hash.game/assets/…` in the middle of otherwise origin-relative markup. Every file the mirror lacks is at `hash.game/assets/<name>`, under the identical content hashes `Enter-MsmOuq5R.js` already lists in `__vite__mapDeps`: chunks, their stylesheets, and the origin-hosted `/assets/…-HASH.png` artwork. `/vip-detail` was built entirely from files pulled that way. Two limits: **source maps 403** (`.js.map` is refused, so you get minified code, not original source), and fetch with PowerShell's `Invoke-WebRequest` — the same libcurl trouble the promotions art hit.

**`hash.game` also answers the LIVE API, unauthenticated, and that changes what "no response was captured" means.** The base is `https://hash.game/api/…` — not `/bc.game/api/…`, which returns index.html. So a path read out of a chunk can be *answered* rather than merely recorded: `/api/edge/home/main/banner/?bannerType=top&…` returned the real home-banner rows behind the signed-in hero, and `/api/activity/recharge-bonus/progress/` returned the real deposit-bonus payload — whose `bonusRatio` 1.8/2.4/3.0/3.6, `extraBonusRatio` 0.4/0.6/1.0/1.4, `minDeposit` 5/10/20/30 in BCD, and `expiredTime` 1788220799999 confirm the `/deposit-offer` reconstruction was right on **every** value. Every "read from saved JS (shape NOT captured)" note in `services/endpoints.js` is now a question that can be settled.

**`/api/game/support/system/conf/…` is the branch of it worth knowing by name**, because it answers where the rest of a signed-in page does not. `usdPrice`, `index/minimal` (the 324-row currency catalogue) and `currencyTokens?currencyName=<COIN>` (186 tokens across the 89 crypto wallets — chains, per-chain minimums, fee ranges, memo-tag names) all came from it, and the last of those is why `/wallet/withdraw` could be built on evidence where `/deposit` had to be built on invention. **Before writing a fixture for anything behind a login, check whether the value is really per-account or merely rendered on a per-account page** — a config the server hands every visitor is often exactly the table you need. The withdraw form's "Min: 204 BCD" fell out of two `system/conf` fields with no reference to the screenshot at all.

Two caveats: a **per-visitor feed answers as a logged-out visitor** (the home banner gives three rows where a real session showed five), and PowerShell's `Invoke-WebRequest` decodes JSON as Latin-1 — use `System.Net.WebClient` with `Encoding = UTF8` or non-ASCII copy arrives as mojibake (`ï¼š` for the fullwidth colon in "Soccer Party ：Bet & Win").

**So the order of work is a ladder, and a screenshot is the last rung.** In order:

1. the mirror, `bc.game/bc.game/assets/`;
2. `hash.game/assets/<name>`, under the identical hashes `__vite__mapDeps` already lists;
3. `hash.game/modules/<remote>/` — if a route resolves through a federated remote (`account`, `static`, `games`) it is **not** in `/assets/` at all;
4. the live API at `https://hash.game/api/…`, where **a catalogue answers and a per-account read does not**. The `game/support` family (`system/conf/*`, `swap/config/`, `buy-crypto/fiats|coins`), `achievement/all/`, `user/game/summary/` and `chat/room/list/` all answer unauthenticated; anything keyed to the session gives 6001/6002 or a bare 403. An AGGREGATE over public data is public, the rows behind it are not;
5. the i18n bundle `index-Dn9m_cUp.js`, which is saved and outlives the chunks it was compiled into — every en-US string on a missing page is still in it;
6. the service module's own `initialValue`, which a login-gated resource often declares as exactly the payload a logged-out visitor renders. That has now supplied four fixtures — `/bonus`, the referral dashboard, the notification drawer and My Profile — with nothing invented;
7. only then a screenshot.

Check for the data separately either way, since chunk and feed are independent (Explore had its chunk and not its feed; Highlights had neither) — and note that a recovered chunk carries markup and i18n strings, not requests. `bc.game/bc.game/api/` holds what the mirror captured; `hash.game/api/` will answer the rest. **Being locked out is often the correct rendering**, not a compromise: several panes here are empty because the real feed refuses everyone, which is precisely what the captures show. Probe the endpoint, record the result, and render the site's own empty state rather than inventing rows.

**Sports is not a page bc.game builds.** Worth knowing before anyone plans work on it. The route is `path: "/sports/*"` in `Enter-MsmOuq5R.js`, its chunk (`index-BzFOqw51.js`) is missing along with `betby-script-*.js`, `useSportsRedirect-*.js` and `Main-*.js`, and the only captured sports response — `api/platform-sports/v14/home/sport/provider/support/` — names one provider, `betby`. bc.game's entire contribution to the rendered page is `#page-content > #betby`, and everything under that is **BetBy's React app inside an open shadow root**: 53 encapsulated stylesheets, styled-components/JSS class names that carry no meaning, `window.BTRenderer` as its only handle. So there is no bc.game markup to transcribe and no bc.game stylesheet to cite — ground truth for this page is computed styles off the live widget, which is a documented exception to how every other CSS file here is sourced. The good news is that BetBy is skinned to bc.game's own tokens (the layer colours, brand green, `secondary`, and avertastd at 16/14/12/10 in weights 400/600, 12px card radii), so it needs no palette of its own. Two traps: its breakpoints are viewport `max-width: 600px / 444px / 412px` media queries with **no container queries**, so forcing its container wide only reflows the mobile tree instead of revealing the desktop lobby; and its mobile/desktop split is decided in JS at init, so measuring it requires a browser window that is genuinely that wide.

Only desktop was captured: the `sm`/`lg` steps in `.sports-grid` are this project's own, not the widget's, and nothing below `lg` has been seen. **BetBy's SVGs are all real assets now** — 29 of them under `src/assets/sports/`, named with BetBy's own filenames minus the content hash (`ic-*` for chrome, `sport-*` for the sports). Two ways in, and the cheap one is worth trying first: the icons are inlined into the shadow root, so pasted `data-cy`-tagged navbar markup from DevTools gives the whole set at once, while `shadowRoot.querySelectorAll('svg')` only reaches what happens to be on screen. Traps if you go the scripted route: fetching the files from `start9.sptpub.com` hangs the renderer, and the Chrome extension redacts long path-data as "Cookie/query string data", which `d.replace(/(.{24})/g,'$1\n')` defeats.

Three things about these files. **They carry no `fill` of their own** — BetBy sets `fill: currentcolor; color: inherit` and colours them from its stylesheet — so a call site that forgets to set one gets solid black. **Strip any `<clipPath>` whose path equals the viewBox** (`ic-badge-hot`, `sport-bc-game-original` both had one): they clip nothing, and since the files are inlined, a duplicate `id="clip0"` breaks every later reference. **Keep prose out of the .svg files** for the same reason — a comment there ships to the browser on every page load.

Two corrections the rendered markup forced, both of which a screenshot had got wrong: the rail's badge is BetBy's `ic-badge-hot` flame with **no counter** (the pin element holds the SVG and no text node — what read as a "6" was the flame), and the rail is **19 sports**, ending Table Tennis then eBasketball, with a Sumo cell where a screenshot reading had put Athletics and Baseball before Cricket. The rail's background is `#323738` (`layer4`), one step lighter than the header, so its hover has to go to `layer5`.

**The rail's whole box is px, not rem** — height, padding and dividers included. Its contents are px-pinned icon boxes, and a container sized in rem around px children grows away from them below 640 (at a 500px viewport `4rem` resolves to 74px around 48px cells). Same rule as the sprites; do not normalise that block to rem for consistency with the rest of `Sports.css`. The bar is **48px**, not 64 — 64 was measured off the widget's *mobile* navbar, which is a taller component. BetBy's own divider rule (`width: 1px; height: 32px; background: rgb(179,190,193)`, i.e. `secondary`) settles it: a 32px divider centred with 32px icons in 48px cells leaves 8px clearance, and there is no vertical padding on top.

Rail hover is **icon-only** — the cell keeps its background, the SVG turns brand green, and a tooltip appears below. That tooltip cannot be a `::after` on the cell: `.sports-rail-scroll` has `overflow-x: auto`, and CSS computes the other axis to `auto` too, so anything drawn below a cell is clipped. It is one element owned by `.sports-rail`, positioned from the hovered cell's `offsetLeft` minus the scroller's `scrollLeft`. The overflow arrow is exempt from all of it — no colour change, no tooltip, and a 24px cell rather than 48 so it sits close to the last sport. The hot pin's white disc lives in CSS, not in `ic-badge-hot.svg`: BetBy puts it on the pin element, and without it the red flame vanishes against `layer4`.

Part of the bc.game rebuild notes. Index and cross-cutting rules: [../CLAUDE.md](../CLAUDE.md).

## Referral

**TWO PAGES THAT SWAP ON SIGN-IN, and reading that pair correctly is the first thing to get right here.** The router carries a matched set of guards — `/referral` has `guards: [() => !b.login && "/referral-exhibition"]` and `/referral-exhibition` has `guards: [() => b.login && "/referral"]` — so each bounces to the other and a visitor only ever sees one of them.

- **`/referral-exhibition`** is the SIGNED-OUT landing page (`NoLoginAffiliatePage`, `index-ve9CyRhD.js`). The captures show a "Sign up & Earn" button, which settles which of the two they are of. Everything below in this section describes it.
- **`/referral`** is the signed-in dashboard (`AffiliatePage`, `index-CgFyS3aK.js`) — see the Referral dashboard section further down.

Both guards are reproduced now, inside the pages rather than in `App.jsx`, because each needs the session. `/referral` used to redirect onto the exhibition page *unconditionally*, since the dashboard was not built and implementing the real guard would have sent a signed-in visitor to the catch-all's silent Home; that stand-in is gone. `/affiliate` is the original's own alias and still redirects one hop behind. The sidebar row points at `/referral-exhibition` for the reason the VIP row points at `/vip-detail` — the row should carry the path that renders for the visitor who is most likely to click it.

Second page built the `hash.game` way, and it should now be the default (see the mirror note near the top). Four chunks came off it — `index-ve9CyRhD.js` (the page), `Questions-dsRHzmFN.js` (Live Rewards, the affiliate band and the FAQ, all three), `servers-O8_t7p5g.js` (the request module) and `utils-PrQ_cjrK.js` — plus nine PNGs. So the class lists are the Solid templates' own and the copy is verbatim i18n, cross-checked against `index-Dn9m_cUp.js`.

**Three dead classes are kept**, and one of them is a trap rather than a nullity:

- `not-full` (the Send Now button) and `contacts-link-item` (the anchor round it) generate nothing, in any of the six stylesheets in the mirror.
- **`l` on the email paragraph is the trap: the class exists.** It is `.wager-item .item-inner .bot .l { opacity: .6 }`, scoped to a component nowhere near this page, so the email renders at full opacity — which is what the capture shows. Do not "restore" the 60% by hoisting that rule.

**`defaultOpen: index === 0` is passed to every FAQ row and is dead**, the same class of finding as `bg-from-special` on the VIP page. The chunk's wrapper builds `<Collapsible><Trigger/><Content/></Collapsible>` without spreading its props onto the Collapsible, so the flag never reaches the primitive — which is why every row in the capture is closed, first included. Note this FAQ is the bare **Collapsible** (`pl`), not the Accordion the VIP FAQ uses: rows here open independently and several can be open at once.

**Only the Live Rewards ticker is screenshot-sourced.** It has a real path (`/agent/affiliate/history/`, read out of `servers-O8_t7p5g.js`) but there is no `bc.game/bc.game/api/agent/` capture, so the four rows are read off the render. Two limits are recorded at the fixture: only the **sum** of `commissionUsd + rewardUsd` is recoverable, since the widget prints the total — the split is not data; and only four rows are legible, which is all the capture holds (the window shows one row, and the red mark under the Hindi name is part of that glyph, not a fifth entry).

**`FILLER_ROWS` in `referral.js` is INVENTED, and it is the only invented payload in the project** — every other fixture here is a captured response or recovered i18n. Sixteen rows were added on request so the ticker has enough height to actually scroll; they sit in their own array beside `CAPTURED_ROWS` (the four the capture holds) specifically so that deleting them is one edit and the evidence stays separable. Remove them when `/agent/affiliate/history/` is connected. Two constraints on anything added there: only currencies with an icon in `src/assets/coins/`, and nothing below 0.01 in a crypto row — the ticker prints at `precision: 2`, so a realistic 0.00042 BTC renders as a bare "+0" (which is what the original does too, and reads as a bug either way).

**The ticker's scroll is gated on overflow, and that gate is ours.** `.live-container` translates by `-100%` of *its own* height, so the window ends every cycle **empty regardless of row count** — the live feed only gets away with it by returning enough rows to keep something in view for most of the 30s. The four captured rows left a ~40px grid in a 48px window and the strip sat blank for most of the loop. A layout effect in `index.jsx` compares the grid's `offsetHeight` against the window's `clientHeight` and toggles `.live-overflowing`, which is what carries the animation. With the filler in place the grid is five rows deep and the gate passes, so the animation runs; strip the filler back to the captured four and it correctly holds still again rather than blinking. `offsetHeight` and not `getBoundingClientRect()` on purpose — the latter includes the animation's own transform and would feed the test its own output. Measured onto the node rather than into state, for the reason the promotions tab indicator is.

**`30s` is a duration, not a speed, and that is why the same effect also sets `animation-duration`.** The keyframes travel `-100%` of the *grid*, so the distance changes with the row count and the pixels-per-second fall out of it — the original's long feed makes 30s a brisk crawl, while our five rows made it ~6px/s and visibly slow. Worse, it drifted with the column count: the same 30s was 6.1px/s at four columns and 12.8px/s at two. The effect now divides the measured height by `SCROLL_SPEED` (30px/s, the one number to turn), which holds the speed constant at every width and stays correct when a real fifty-row feed replaces the filler — where a literal 30s would suddenly be several times too fast. The `30s` in `Referral.css` stays as the original's value and is what renders if the effect never runs.

**Do not pin `maximumFractionDigits` in the currency formatter, and do not trust node when checking it.** The ticker's apparently inconsistent rows — `IDR 268`, `₹1.26`, `0.1`, `12` — all come off one call: `printCurrency`'s currency argument defaults to `USDFIAT`, a `*FIAT` target goes through `Intl.NumberFormat(style: "currency")` on the code with the suffix stripped, and en-US spells IDR as its code and INR as its symbol. The zero decimals on IDR are CLDR's, which `toFiatStr` reads back out of `resolvedOptions()`. **Node 24's ICU 77 answers 2 for IDR and renders `IDR 268.00`**; Chrome answers 0 and matches the capture. The browser is what ships — verified there, along with `'en'` and `'en-US'` agreeing.

Geometry checks out against the capture at dpr 1.25: the 1216 container, the hero at exactly `sm:h-64`, `gap-4` between every block, and a 40px FAQ row pitch (a 24px chevron box over `gap-4`). Two things about the layout that read as mistakes and are not: the wide space in "Learn more about our **affiliate program**" is the heading's own `sm:flex gap-3` putting 12px between two anonymous flex items, not spaces in the string; and the Live Rewards card is the one block on the page that stacks until **768** (`md:flex-row`), not 640. `ee.mobile` is read as the 640 line here for the reason VIP documents — the artwork has to swap with the layout that uses it, and that layout is `sm:`.

**Two spacing departures, both one-word reverts**, and both are the page giving up the only margin it owns rather than anything shared: the hero's `sm:mt-6` is dropped, and the lower block's `mb-3` with it. What is left at each end belongs to the layout — `--header-mb`'s 12px at the top, `.footer-bg`'s 1rem at the bottom (itself this build's, not the original's) — and trimming either would reach every route.

**The top gap has a floor that is not spacing at all, and it is worth knowing before anyone chases it again.** `banner_right.png` is 1366×822 but its opaque ink spans only y 162..780. At `sm:w-[600px]` the element renders 361px tall, so under `sm:items-center` it **overflows the 256px (`sm:h-64`) card by 52.5px each way**, and the artwork's own transparent margin lands the first visible pixel 18.7px *below* the card's top edge — measured at 18.4 in the capture. Header-to-artwork therefore bottoms out near 31px on desktop no matter what the margin says; lower means changing `--header-mb` globally or cropping the PNG. Below 640 none of it applies: `--header-mb` is 0px and the margin was always `sm:`-only, so the banner is already flush there.

`.button-second` was added to `@layer components` for this page (index-DxOqNczA.css verbatim, over the `button_bright` token) — layered like the rest, because the reward cards write `w-full bg-layer5` over it.

### The Refer and Earn dialog

What the sidebar's Refer row opens — `src/components/modals/Refer/`. **It is not a route and there is no `/refer` path**: `Enter-MsmOuq5R.js` listens for an `open-refer` event and pushes `Refer-DVueC7AK.js` onto the popup stack, whose default export is three lines. The chunk came off `hash.game/assets/`, is 2.5 KB, and holds the whole dialog — so the template, both `text-3xl` spans and every class list are the original's.

**The row that opens it is the one entry in the entire sidebar menu whose `link` is not a path.** `index-DuwOs_Mv.js` gives it `link: "refer"` with `label: () => ""`, and `le` in `NavItem--aJiS2FS.js` special-cases `buttonName === "sidebar_promotion_refer"` into a branch that supplies its own label — `t("Refer and Earn")`, which is why the printed name comes from nowhere in the menu data. `action: 'refer'` is this build's name for that marker; the row had been left deliberately inert with the label written as "Refer & Earn", and both are corrected.

**The headline is one i18n value with five slots, not five strings laid out by eye.** `bonus.mainpage.refer.desc` is `<0>REFER A FRIEND AND GET</0><1>__number__</1><2>+</2><3>15%</3><4>COMMISSION</4>`, and the chunk hands `<Trans>` a `number` of `printCurrency(new Decimal(1000))`. Slots 0 and 4 carry `block` — that is what puts COMMISSION on its own line instead of trailing the 15%, and it is the kind of thing a screenshot rebuild gets right by accident and then loses. `__number__` is not a constant in disguise either: `printCurrency` reads the account's display currency, so the same 1000 follows `enableLocaleCurrency` wherever it points.

**One thing on the dialog is invented and it is the link.** `/agent/invitation/code/custom/` answers 6002 like every other `/agent/` path, so unlike the withdraw form there is no `system/conf` sibling to recover it from. What *is* known is the shape off the rendered field, `https://<host>/i-<code>-n/`, so `services/referral.js` builds it from the fixture account's own `currentInvitationCode` rather than a made-up string — which keeps it consistent with the signed-in AffiliatePage, whose invite card and Referral Codes table print the same value from the same `INVITE_HOST`. The host is `hash.game`, the captures' own; it was `bc.game` for a while and the reversal is explained under Referral Codes & Friends, where the string's width turned out to be load-bearing. The response's `invitationCode` is returned alongside because the APP branch (`isAPP && host.includes("bcgameapp")`) swaps the whole URL for a landing-page one built from it; that branch is unreachable in a browser build and is not reproduced.

Two departures, both flagged at their call sites. **The copy confirmation is on the button**, because `m(o("Copied"))` is a toast and this build has no toast system — lift it the day a second thing needs to say something, the same rule `Select` and `GameTile` moved under. And **the logged-out branch is the caller's rather than the dialog's**: `Z` checks `account.login` in its own mount effect and, if false, pops itself and navigates to `/login/signin` — a dialog that closes itself on the frame it opens, which in React means calling a parent's setter from an effect. The decision is made in the sidebar's handler instead, where the observable behaviour is identical. The row carries `needLogin` anyway, so nobody who could take that branch can see it.

**It is also what finally forced `--text-xl--line-height` into `@theme`.** The original tightens two steps of the type scale, `text-xl` to 1.5rem and `text-2xl` to 1.75rem, and only the second was declared — `text-xl` was left out on a note saying nothing used it yet. The headline here is a `text-xl` block wrapping a `text-3xl` figure, so its two outer lines were rendering in Tailwind v4's 28px box against the original's 24 and the card came out 8px tall. Declaring it reaches every `text-xl` that lets the step decide; most call sites are immune either way, since `Contest`'s countdown digit sits in a fixed `h-15`, PokerTab's heading in an `h-8 flex`, and the hero banner and HowToDeposit write their own `leading-*`.

The fetch is **gated on `open`**, because the original's runs from the dialog's own mount and this component stays mounted across the closed state. That used to cost nothing, because `client.js` answered fixtures synchronously; it costs a real request now that a fixture takes time, which is why opening the dialog is what starts the read rather than loading the page. The link field carries the site's 12px inline spinner (`[&>.loading]:size-3`) until it lands.

## Referral dashboard

`/referral` — the SIGNED-IN half of the pair above, `AffiliatePage`, `index-CgFyS3aK.js` off `hash.game/assets/`. Sign in on `/referral-exhibition` and the guards swap you onto it.

**THE FIXTURE IS THE REQUEST MODULE'S OWN DEFAULT, which is the second time that has paid.** `hash.game` answers every `/agent/` route 6002, so neither `/agent/affiliate/dashboard/` nor `/agent/invitation/code/custom/` can be fetched — but `servers-O8_t7p5g.js` (which **is** in the mirror) declares `m`, the object the store falls back to, and it is exactly what the capture renders: every figure `"0"`, `friendNumber: 0`, both activity lists empty. So the whole right-hand stat column and the Rewards Activities empty state are recovered rather than reconstructed. Same trick as the bonus page's `initialValue`; **check for one before writing any login-gated fixture.** The invite card's link and code are the one exception and they were already solved — `getInvitationCode` derives them from the fixture account's own `currentInvitationCode` through the `i-<code>-n` shape read off the capture.

**ALL FOUR TABS ARE BUILT.** The strip is the chunk's own — labels, icons and the URL each navigates to, out of `A = ["referral","my-rewards","refer","rules","banners"]` and its `p(r)` switch, which is why My Rewards and Referral Codes each carry a default sub-tab in the path while Dashboard is the bare `/referral`. The four panes are `index-CgFyS3aK.js` itself, `index-Deo68lWp.js`, `index-CC3wjKfm.js` and `index-B5gBp3du.js`, all off `hash.game/assets/`; each has its own section below. `/referral/*` is ONE route here rather than the original's layout-plus-children, since the panes are switched inside the page.

**`class` ON A `TabItem` BELONGS TO THE CONTENT PANEL, NOT TO THE BUTTON — and this is the second page to get that wrong, so treat it as a rule rather than a note.** The deposit dialog documents it already (see Deposit); here the chunk's wrapper is `P(i) = t(r1.TabItem, {class: L(i.class, "mb-4 mt-4 flex-1 bg-transparent font-semibold"), title, children})`, and putting that list on the trigger broke both halves of what it is for. `bg-transparent` is a utility, so it beat `.tabs-btn[aria-selected]`'s layered `background-color: var(--color-tab_selected)` and **the active tab lost its pill** — the whole strip read as unlit. And `mt-4 mb-4` is 32px of vertical margin inside a `.tabs-title` whose content box is exactly 32px, so every button collapsed and its label sat off centre. On the panel, where they belong, the same two classes cancel `.tabs-content`'s layer4 fill and open the 16px above the pane — which is the gap between the strip and the invite card, and beats `.tabs-content`'s own `margin-top: .5rem` because a utility outranks the layer. The `!bg-transparent` this call site used to write on the pane was a compensation for the misplacement and is gone. Only My Rewards passes an `i.class` of its own (`[&_.scroll-x>button]:flex-none [&_.scroll-x]:w-auto`, reaching into a pane that is not built); it rides along in `TABS` as `paneClass`. Note the four tabs split the 800px evenly because `.tabs-btn` carries its own `flex: 1` — the `flex-1` in that list is not what does it.

**THE NINE SOCIAL MARKS ARE BASE64 PNGs INLINED IN A CHUNK, not sprites and not SVGs** — worth knowing before hunting for them anywhere else. `ShareIcon-CMaOnZIq.js` is 30 KB holding NINETEEN data URIs in one array, and its whole component is `<img src={m[types - 1]}>`. They are decoded back to files under `src/assets/referral/socials/`. **Which nine is decided by a filter, not by the list**: `ox` in the main bundle builds fourteen entries and the call site drops any whose `name` is "email" or whose `url` is undefined, which removes email, `vertical`, `btc`, `pinterest` and `reddit` — leaving exactly the nine in the capture, in that order. Each entry's `icon` number is the 1-based index into the array and is recorded in `socials.js` so the mapping stays checkable.

**Four dead classes are kept** — `invite-top`, `top-inner`, `activities-wrap`, `bot-info` — and they were checked against the mirror's `index-DxOqNczA.css` **and** the current deploy's `index-DGr5jguQ.css`, which is a different file from a later build. Absent from both, so they are kept for the reason `page-main` and `header-nav-item` are.

**Three components moved under the second-call-site rule, and the move is the chunk's own arrangement rather than a convenience**: Live Rewards, the affiliate-programme band and the FAQ are `Questions-dsRHzmFN.js`'s three exports, and BOTH referral chunks import them from it. They now live in `pages/Referral/blocks.jsx`, with `printCurrency` / `fill` / `SCROLL_SPEED` split into `pages/Referral/format.js` beside them (`react-refresh/only-export-components` forbids a file exporting a component from exporting anything else — the same reason `useSession` is not in `SessionContext.jsx`, and the same reason `socials.js` is not part of `icons.jsx`). Kept in `pages/Referral/` rather than lifted to `components/shared`, because both call sites are this one page family.

`__friendAmount__` was the one placeholder `fill` did not know, and it takes the same value as the exhibition page's `__localAmountStr__` — the chunk fills both with `printCurrency(1000)`, which is also the green figure printed directly above the sentence. They share one alternation for that reason.

Not built, each inert at its call site: the Copy buttons write to the clipboard but the toast that confirms it is the site's global one; `/referral-terms` is a real route on the original and falls to the catch-all here; and the share links open a real sharer with the invite URL, where the original first shortens it through `POST /game/support/share/short-link/<platform>/` — for Facebook, X and Telegram only.

The terms link carries `button-m`, which is `ot`'s own and was missing. `.button`'s base height is **3rem**, `.button-m`'s is 2.5 — so a 48px button pinned at `top-4` put that line's centre at y=40 where the card's `py-6` over a 24px `text-xl` line box puts the heading's at y=36, and it read as sitting low. It is the same miss the Select call sites are documented for; check for it wherever a `.button` here has no size class.

### My Rewards

`/referral/my-rewards/:pane` — the second of the four tabs, `index-Deo68lWp.js` off `hash.game/assets/` with `table-DWtoUmQ7.js` beside it. Nothing on it is read off a screenshot.

**BEING LOCKED OUT IS THE CORRECT RENDERING**, which is the transaction pane's finding a second time. All four feeds are authenticated and all four are shut — and in two different ways, which is worth recording because "no capture" and "no answer" are different problems: `/agent/commission/list/` answers bc.game's own 6002 envelope, while `/agent/information/list/`, `/agent/invitation/code/list/` and `/agent/information/referral-rewards/list/` answer a bare gateway 403. Probed rather than assumed. So the summary card prints the request module's default (every figure "0", already in the project as `DASHBOARD`), both buttons take their own disabled gate, and all three panes render the site's empty state — which is exactly the capture, arrived at without inventing a row.

**THE INNER SEGMENT NAMES DO NOT MATCH THEIR LABELS**, and reading the path is not enough to know which pane is open: `C = ["friends","commission","referral"]` maps in declaration order to Commission by **Friends** / Commission by **Currency** / **Level Up Rewards**. So `commission` is the by-currency pane and `referral` is the one whose label contains neither word. The strip's own tab is the last path segment (`Re(pathname)`), not a route parameter.

Four more things the chunks settle:

- **`table-DWtoUmQ7.js` is NOT `components/shared/Table`.** That one is `Table-Cyxc_MMr.js`, the wallet panes' stack of `flex justify-between` rows whose cells the call site writes out. This is a real `<table>` driven by a `columns` array of `{title, dataIndex, render}` against `data`. Same word, two chunks, two APIs — add it to the `IconInform` / Vault Pro list of names that are shared and drawings that are not. Ported as `pages/Referral/DataTable.jsx` and kept local for the reason `PillTab` is: the original imports it from two places and only one of them is built. Its alignment is **positional** — first column left, last right, everything between centred, header and body alike — so a column's place in the array is what decides how it reads.
- **Both ⓘ popups are recovered verbatim, not transcribed.** Each body is one i18n value with its headings and paragraphs as numbered slots (`bonus.affiliate.rewardtip1` / `rewardtip2` in `index-Dn9m_cUp.js`, which is in the mirror), and the chunk hands `<Trans>` its six templates in slot order — so the array order in `REWARD_TIPS` **is** the display order and none of the pairing is inferred. The second popup reuses the first's "The rewards you can withdraw to your wallet." under a different heading; that repetition is the bundle's own.
- **The code dropdown is seeded and appended to, not replaced** — the same arrangement the rollover pane's Bonus Type filter has. It starts at `["All Codes"]` and pushes one `aliasCode` per row, so an empty response leaves exactly that one option, and `All Codes` is a real option (the request strips it) rather than a placeholder.
- **Two dead classes are kept**: `sub-num` on the two right-hand figures, absent from the mirror's six stylesheets and the current deploy's alike; and `pc:gap-10` on the currency row, which is dead for a different reason worth knowing — **`pc` is not a breakpoint on the original.** `.pc` is a plain class carrying `--footer: 0rem` and the variant resolves against it, so this build, which has neither that root class nor the variant, emits nothing. The row keeps `gap-14` at every width, which is the desktop capture anyway.

Not built, each inert at its call site: the **date range pickers** (`fT` in the main bundle is a 720px calendar layer over a preset rail; its trigger — the `.input` primitive in `readOnly` with the range as its value and the label as an `order-first` child — is built and its layer is not, and there is nothing to filter behind them), the `/rewards-detail` and `/friends-detail` row links, the `/rewards-swap` and `/rewards-withdraw` routes behind the two buttons, `/reward-history` behind the History button, the pager under each table (`total > 10`, which no empty list reaches) — but the skeleton the chunk shows while a table is pending IS built, and it is what separates this pane's two gates: the summary card waits on `/agent/affiliate/dashboard/` and blanks the pane, the table waits on its own list call and takes the pulse. See Loading states.

`AfterLogin/icons.jsx`'s `Icon` wrapper now forwards anything past `className` to the `<svg>`, because the original puts handlers straight on the icon — the summary card's two ⓘ marks are `IconInform({class, onClick})` with no wrapper element — and adding a `<button>` around them would have changed the markup to work around the component.

**THE RULES/HISTORY PAIR AND THE HAIRLINE UNDER THE STRIP ARE SIBLINGS OF IT, NOT ITS CHILDREN, and that is the Tabs component's own arrangement rather than a layout choice.** `iT` returns `[<div class="tabs-title">…</div>, <Show>{the content panel}</Show>, Ae(() => t.children)]` — so anything a call site passes *besides* its `TabItem`s renders **after** the panel, and `TabItem` itself returns `null` and merely registers into a context. Both of these elements are absolute, so what they resolve against is the pane's own `section.relative` and nothing else. Put inside `.tabs-title` — which is `position: relative` in its own right — everything shifts down by the section's `pt-2`: the buttons land 8px low and the `top-12` hairline lands 8px *below* the strip's bottom edge instead of exactly on it, which reads as a stray border floating over the pane. Against the section the arithmetic is exact: 8px of `pt-2` plus `.tabs-title`'s own 2.5rem is 48px, which is `top-12`. Worth checking on any other strip that passes extra children.

### Referral Codes & Friends

`/referral/refer/:pane` — `index-CC3wjKfm.js`, 6 KB, and one file is the whole tab: a two-figure card with a Create Code button over a table of the account's invite codes.

**THIS IS THE ONE REFERRAL TABLE WITH A ROW IN IT, and the row is not invented.** `/agent/invitation/code/list/` answers 403 like every other `/agent/` route, but its payload is one entry per code the account has created and this account has created exactly one — the same code the Dashboard's invite card and the Refer and Earn dialog already print. So `services/referral.js` derives it from `SIGNED_IN.currentInvitationCode` through the same `i-<code>-n` shape, and the three surfaces cannot disagree. `createdNum: 1` against `totalCodeNum: 20` is the capture's own pair and the second figure is the **cap**, not a count — the card reads "1/20". `ratio` 0.25 is the 25% the invite card states and the Rate & Rules calculator opens on.

**That is also what corrected the account fixture.** `currentInvitationCode` was `BCGAMER`, invented while nothing rendered it; the capture shows `98q7ntrof8` beside `…/i-98q7ntrof8-n/`, and three surfaces now derive from that one string. Only `createTime` has no source and is stamped at module load rather than pinned, on the same reasoning as the deposit bonus's month reset — nothing derives anything from it, and a date that is merely today's reads better than one that is simply wrong.

**`IconCopy` in `components/shared/icons.jsx` WAS THE WRONG DRAWING, and it is corrected.** It was labelled `IconCopy-i40gX7iJ.js` and was not that file — its path (a pair of square outlines offset by a third of their width) appears in no file in the mirror and in no chunk fetched off `hash.game` since, so it was presumably read off a capture when the deposit dialog was built without its chunk. The mirror's actual `IconCopy-i40gX7iJ.js` is a single-path stacked-sheet mark, which is what the capture shows. **Both consumers really do want that one** — `index-C1xohM7W.js` lists `assets/IconCopy-i40gX7iJ.js` in its `__vite__mapDeps` and `index-CC3wjKfm.js` imports it by name, checked in both rather than assumed, because replacing a glyph two pages draw is not worth doing on one page's evidence. Note `pages/UserEnter/icons.jsx` already carried the correct path under a different label, and the note beside it saying the two modules hold different IconCopy drawings **was true and is now not**; fold that copy in when a fourth consumer appears.

**The two copy buttons in the table are not the same component on the original**, and the difference is where the handler sits: the Code cell puts `onClick` on the **button** with a plain `size-5 fill-secondary` icon, while the Link cell leaves the button handler-less and puts `onClick` on the **icon**, which is why only that one carries `cursor-pointer` and a `p-0` of its own. Identical to use; reproduced because it reads as a transcription slip when it is the chunk's. `components/shared/icons.jsx`'s wrapper now forwards props past `className` so the icon can take a handler at all, as `AfterLogin/icons.jsx` and `pages/UserEnter/icons.jsx` already did.

**THE TABLE HAS NO COLUMN WIDTHS AND MUST NOT BE GIVEN ANY — two attempts were made and both are reverted, and the second is the instructive one.** The chunk sets none, so Chrome sizes each column from its content and distributes the leftover unequally, by a rule that depends on each cell's exact text. That makes the layout a pure function of the row data, which is the property worth keeping: a call site whose rows match the capture's matches the original with nothing tuned. Here they nearly do — the one difference is that `getInvitationCode` builds the link on `bc.game` where the captured session was served from `hash.game`, four characters shorter, which narrows the Link column and pulls everything after it left by ten or fifteen pixels. **Correct the ROW, not the table**; changing that host is a one-line fix that makes the layout identical by construction, and it is left alone only because two other surfaces print the same string.

**And the row is now corrected: the invite host is `hash.game`, reversing an earlier choice.** It was written as `bc.game` on the reasoning that the two are the same deploy and this is a bc.game account, treating the capture's `hash.game` as an accident of which origin answered. That reading is defensible right up until something *measures* the string — and this table does, because the URL sits in an auto-layout column, so four missing characters redistribute the whole row: the Code column moves right as the leftover pool grows, and the three columns after the link move left as it shrinks. Both directions at once, from one cause, which is what identified it. The original builds the link from `location.host`, so on the live site it is simply whatever origin served the page; the captures are the only evidence of what it renders as and both say `hash.game`. Evidence beats the tidier reading, the same call the deposit-offer scroll lock documents. `INVITE_HOST` in `services/referral.js` is the single definition, because three surfaces print it — the Refer and Earn dialog, the dashboard's invite card and this table.

The failed attempts are worth recording so they are not repeated. Widening the cell padding moves the middle columns outward by an amount that is *itself* content-dependent, so it approximates rather than matches — it turned "too far in" into "still too far in". Pinning a `<colgroup>` with `sm:table-fixed` is exact, but the percentages have to be measured off a screenshot, and **that measurement did not survive checking**: three independent ways of recovering the capture's scale (the card's known width, the table-edge algebra, and the width of a known string at a known font size) disagreed by 40%, and the widths they produced put the Date column *below* the width its own text needs — which cannot be true of a layout that visibly renders it. The result looked authoritative and was not, and it moved the columns the other way. **This is the general trap with screenshot geometry in this project: a measurement that cannot be cross-checked against something with a known size is not a measurement.** Sports.css gets away with it because every figure there is divided by a devicePixelRatio that was independently established.

**The pager is client-side**, and note it counts `createdNum` rather than `list.length`: the feed returns every code in one response (`pageSize: 20` against a cap of 20) and the component slices it, so the control changes nothing about what is fetched. `components/shared/Pagination` gained an `end` arm on its `align` prop for it — the chunk writes `class="flex justify-end p-3"` on the component, where this build's copy carries its own spacing. Not built: the Create Code dialog's submit (`POST agent/invitation/code/add/`; the dialog itself is built, since the chunk carries all three of its parts — and note it posts the one field as **both** `invitationName` and `campaignName`), the `/referral-code-detail` route behind the Referrals arrow, and the toast each Copy raises.

### Rate & Rules

`/referral/rules` — `index-B5gBp3du.js`, 16 KB.

**THIS PANE HAS NO FEED AT ALL, which makes it the only one of the four that is complete rather than complete-and-empty.** The rate boxes are literals in the markup, the Unlock Amount table is a **hardcoded array in the chunk** (ten rows of `{icon, Level, wager, amount}`), and the calculator is arithmetic over three inputs. Nothing was gated and nothing is inferred.

**The level names and colours are NOT in that array**, and where they come from is the useful part: it stores a bare `Level` number and `u1` looks the rest up through the VIP ladder — `vipLevelRow(n).tier` for the name, `tierColor(tier.base)` for the icon's inline `color`. `src/data/vipConfig.js` is that ladder, the captured `/game/support/vip-v2/config/` response already in the project for the Bonus page's level card. Ten levels — 1, 2, 4, 5, 7, 8, 9, 10, 12, 14, not contiguous — resolve to Bronze I / Bronze II / Bronze IV / Silver I / Silver III / Silver IV / Gold I / Gold II / Gold IV / Platinum II, **which is the capture's list exactly**, arrived at without reading it. `wager` keeps the chunk's own formatting, un-grouped "1000,000" included.

Three more things the chunk settles:

- **The calculator reproduces the capture to the digit and the `1e4` is the reason.** `wager × commissionRate / 1e4 × gameRate`, floored to 2dp — the divisor is the two 1% factors the rate boxes spell out, so the rate is a percent of a percent. 1000 × 25 / 10000 × 0.28 = 0.70, which is what the capture prints. The Game dropdown has **four options and three rates**: 3rd Party Slots and Live Casino are separate entries both at 0.6, which is also how the rate boxes group them.
- **`View Rules` is one button with two signals, so a desktop visitor's chevron never rotates.** `S.mobile ? d(o => !o) : push(D1)` — the inline expansion and the popup are different things and the chevron reads the inline one. Both arms are wired here, unusually for an `S.mobile` branch, because the mobile arm is a state toggle rather than a second layout; `?rule=open` seeds it, which is the one way a desktop visitor reaches the inline copy.
- **The calculator's two error messages can never render.** `r()` returns a fresh object with `wager: 0` and `commissionRate: 0` on every call, so `!!r().wager` is always false. All four strings are real and the branch is dead; reproduced as the constant it effectively is rather than dressed up as validation that works.

The four tier marks came out of `IconNblevelsilver-CYvOpWLl.js` — one chunk holding all four, which is why it is named after only one of them. Bronze is the only one with a real `<clipPath>` (its rect is 4.371,3 to 27.161,29, so it clips something and cannot be stripped the way a full-viewBox one is); its id was the single letter `b` and was renamed, since inlining a duplicate id breaks every later reference. The gold coin beside each amount is a **base64 PNG inlined in the chunk**, decoded to `src/assets/referral/coin_gold.png` — the same arrangement the nine social marks have, and the second place in this family where the artwork is in the JS rather than on the CDN. `data`, `text` and `w` are dead classes and are kept.
